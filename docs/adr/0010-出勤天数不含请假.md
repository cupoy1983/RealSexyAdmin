# 出勤天数不含请假

出勤天数改用自算口径「**应出勤 − 旷工 − 请假天数 + 休息日里干净上班的天数**」，
不再采用钉钉「出勤天数」原值 —— 因为钉钉把带薪病假也算进了出勤。

> 2026-10-30 建立。起因：用户发现 9 月（30 天、休息 5、旷工 1、请假 1）出勤显示 24，
> 而自己算是 23。差的 1 天正是钉钉算进出勤的那 1 天病假。
> 这是对 ADR-0002「以钉钉月报为准」的第二次偏离（第一次在 ADR-0009 公司休息日）。

## 一、钉钉口径 vs 新口径

钉钉的「出勤天数」= 正常 + 外勤 + 缺卡 + **病假等带薪假**，即「应出勤 − 旷工」，
把请假也算作出勤。以员工甲 9 月为例：正常 19 + 外勤 1 + 缺卡 2 + 病假 2 天次 = 24。

用户拍板：**请假（病假/事假/年假）一律不算出勤**（A 方案）。但半天假里「工作了的那半」
算出勤，所以减的是请假**天数**（浮点，0.5 算半天），不是请假的日历日数。

```
出勤天数 = 应出勤 − 旷工 − 请假天数 + 休息日里干净上班的天数
```

- 应出勤、旷工：仍取钉钉原值（整数，日历日）；
- 请假天数：`leave_personal + leave_sick + leave_annual`（浮点，半天 = 0.5）；
- 「休息日里干净上班的天数」：公司休息日里钉钉判「正常/外勤」的天数（ADR-0009 A4 算上班），
  加回来是因为这天已不计入应出勤，但人确实来上班了。

## 二、为什么是浮点列

半天假会让出勤带 0.5（如某月有 0.5 天病假，出勤 = 整数 − 0.5）。
所以 `actual_days` 从 `Integer` 改成 `Float`（迁移 `2026_10_30_1822_84640c35529a`）。

## 三、与休息日重算的关系

出勤不再像其他统计列那样按「基准 + 增量」逐条调，而是**统一按上式推导**：
重算时先把 应出勤/休息/旷工/异常/请假 按休息日规则调好，最后一步算出勤。
`dingtalk_raw` 快照里仍保留钉钉的「出勤天数」原值（24），用于和钉钉对账；
页面上展示的 `actual_days` 是自算口径（23）。

## 四、代价与边界

- **与钉钉月报数字对不上**：钉钉导出报表的出勤是 24，我们显示 23。对账时要知道差的就是请假。
- **影响所有月份**：这是全局口径，不只作用于有休息日的月份；没有任何休息日的月份，出勤也从钉钉值变自算值。
- 「迟到/早退/缺卡/外勤」在新口径里**算**出勤（用户确认，与钉钉一致）。
- 病假等**全天**请假：那天贡献 0 出勤（请假天数 = 1，应出勤 − 请假 = 当天 0）；**半天**请假：贡献 0.5。

## 五、2026-11-11 补记：应出勤被截短时，自算出勤会跟着短

本 ADR 的公式 `A = R − 旷工 − 请假 + 休息日里干净上班的天数` 以钉钉的 R 为起点。
R 是**按人按天累加的个人列值**：月中入职 / 未加入考勤组时，钉钉只返回被记到的日期，
R 会被截短（2026-10 `oa_user_id=10` 为 9，同组标准 23），旷工／请假又都是 0，于是 A 也被截成 9，
`A / R = 1`，工资被算成整月全额。

- **本 ADR 的自算公式不变**，仍是权威的 `actual_days` 口径；
- 折算分母的修正放在薪资侧：ADR-0011 第十一节把 R 抬平到全组统一值，公式仍是 `基础工资 ÷ R × A`；
- **实出勤按「实际到岗天数」认定**：11–13 号上班没打卡、14–20 号不在考勤组打卡，
  钉钉漏记的 9 天由管理员人工认定（11 号到月底共 18 天到岗）。系统里这些天属于
  `empty`，`PAID_REST_CATEGORIES` 不含 `empty`，代码**不会**把它们自动算成到岗，
  也不会算旷工、不报错（ADR-0014 第四节）。因此今后同类情况须在钉钉补卡／加入考勤组后
  重拉，或走 ADR-0011 第十二节的一次性订正；系统不臆造到岗证据。
