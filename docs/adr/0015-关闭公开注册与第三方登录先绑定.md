# ADR-0015（已废止）：关闭公开注册与第三方登录「先绑定、后登录」

- 状态：**已废止**；A3 / A5 相关代码已于 2026-11-07 / 2026-11-08 全部回退
- 原决策日期：2026-11-06；废止日期：2026-11-08
- 关联：ADR-0013（用户必填与角色边界）、ADR-0006（框架文件清单第二节）、ADR-0001（外部账号绑定统一模型）

> **本篇不再描述现行设计。** 保留 ADR 编号与文件名，仅供追溯「曾经做过什么、为什么撤回」；
> 现行行为以代码为准，见第三节。任何新功能设计都不要引用本篇的 A3 / A5 条款。
>
> **例外**：原 A4「Excel 导入补齐角色列与手机号行级错误」仍有效，现行规则见 ADR-0013 第 1 节，
> 不在本次废止范围内。

## 一、原决策是什么（一句话）

2026-11-06 因 ADR-0013 把 `UserCreateSchema` 的 `mobile` / `dept_id` / `role_ids` 改为必填，
公开注册、第三方 OAuth / 微信自动建号、微信手机号登录三个旧入口构造不出合法入参。
当时的处理是：关闭公开注册（A3）、取消第三方自动建号改为「先绑定、后登录」（A5），
并把 `gitee_login` / `github_login` / `wx_login` / `qq_login` 四个字段放进
`ThirdPartyBindingSchema`，由 `UserCreateSchema` / `UserUpdateSchema` 继承，
即**由管理员在后台新增 / 编辑用户时维护绑定**。

## 二、为什么废止

**需求从一开始就被理解错了。** 用户 A29 明确并三次重申：
要的是「**用户自己绑定自己的微信等**」，不是「管理员在后台绑定」。
`ThirdPartyBindingSchema` 及其「只允许管理员后台维护」的设计，是助手误判绑定主体后
自行加进去的，用户从未要求过；后端也从未有「用户自助绑定」的接口，两者不是同一条路径。

用户拍板回退：

- A21：先回退之前因前台注册报错而修改的代码，报错留待后面统筹优化；
- A27 YES：回退「关闭注册 / 第三方先绑定」那批框架代码；
- A33 YES：补回退遗漏的 `ThirdPartyBindingSchema`；
- A32：接受回退后旧入口因 ADR-0013 必填 schema 仍会报错，属已知状态。

用户另已明确：首页／前台改版 H1（含第三方绑定入口）移交外部开发者，本项目不跟进、不实施。

| 四个 `*_login` 字段 | 只剩框架原版：`sys_user` 表列、`CurrentUserOutSchema` 出参、前端类型定义与 `profile.vue` 展示；**后端无任何写入入口** |

已知状态（用户 A32 接受、A21 留待统筹优化）：`register()` 与 `auto_register_login_user()`

旧入口之间的待优化项。

## 四、真实需求归属

「用户自己绑定自己的微信等」是**用户自助绑定**，需要独立的当前用户绑定接口
（框架原版 `CurrentUserUpdateSchema` 不含这四个字段，`profile.vue` 只展示不绑定）。
该需求属首页改版 H1，已移交外部开发者；本项目不提供该接口，也不再保留
「管理员后台绑定」的任何设计、字段继承或文档条款。
