# ADR-0013：系统用户新增与编辑的必填项及角色边界

- 状态：已确认，已实施并验证
- 日期：2026-11-05
- 范围：系统管理 → 用户管理的新增与编辑

## 背景

此前后端 `mobile`、`dept_id`、`role_ids` 均为可选，前端未对部门与角色做必填校验，
且表单暴露「是否超管」开关。管理员可凭此直接创建出超管或管理员账号，形成越权通道。

新建 OA 用户还会联动创建钉钉通讯录成员，而钉钉侧创建必须要有手机号；
手机号留空会导致「OA 用户建成了，钉钉账号创建失败」的半截状态。

## 决策（用户逐条确认的 A1–A6）

### 1. 必填项

新增与编辑时，`mobile`、`dept_id`、`role_ids` 三项均为必填。

前端表单加必填规则，后端 schema 同步强制，**不能只靠前端隐藏或提示**。

### 2. 角色边界（双重限制）

- `is_superuser` 必须为 `false`；
- 角色只能是 `USER`，不允许出现 `ADMIN`、`SUPER_ADMIN`。

两条同时成立才算「普通用户」。仅挡 `is_superuser` 不足以限制权限，
因为 `ADMIN` 角色本身就带管理权限。

### 3. 作用范围

新增与编辑**都**受限。编辑时同样不允许把他人提升为管理员或超管。

### 4. 超管豁免

`is_superuser = true` 的账号不受上述任何限制，可创建、编辑任意角色的账号。
否则将没有任何入口再建管理员账号。

### 5. 管理员不能编辑高权限账号

管理员（非超管）**不能编辑** `ADMIN` 或 `SUPER_ADMIN` 角色的账号，包括基础信息。
此类账号只能由超管维护。

理由：若允许改基础信息，手机号被改会影响钉钉账号匹配，角色被改可直接降级他人权限。

### 6. 存量用户不动

不批量补齐历史数据的手机号、部门、角色，仅约束新增与编辑时的提交。

## 影响

- 前端：表单必填规则、超管开关的显隐、角色选项过滤、编辑按钮的可用性。
- 后端：schema 必填校验、service 层的角色与目标账号双重校验。
- 钉钉联动：手机号必填后，新建用户的钉钉创建不再因缺手机号而失败。
- 部门映射（`iac_account_dept_mapping`）仍需手工维护；部门未建映射时，
  OA 用户可建成，但钉钉侧创建会失败并提示。

## 验证要点

1. 管理员新增用户缺手机号 / 部门 / 角色 → 前端与后端均拒绝。
2. 管理员新增用户携带 `is_superuser=true` 或 ADMIN 角色 → 后端拒绝。
3. 管理员编辑 ADMIN/SUPER_ADMIN 账号 → 后端拒绝。
4. 超管新增 ADMIN 账号 → 允许。
5. 存量无手机号用户不受影响。
