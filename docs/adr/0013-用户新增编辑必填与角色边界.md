# ADR-0013：系统用户新增与编辑的必填项及角色边界

- 状态：已确认，已实施并验证
- 日期：2026-11-05（2026-11-06 修订）
- 范围：系统管理 → 用户管理的新增与编辑
- 2026-11-06 修订（缺陷复核 BUG-03 / BUG-08 / BUG-11 / BUG-12，用户 A3 / A4 / A5 / A8 拍板）：
  必填 schema 上线后，公开注册、Excel 导入、第三方自动建号三个旧入口全部失效；
  且「不能编辑高权限账号」只接到了 `update()`，重置密码 / 停用 / 删除是越权口子。
  修订内容见第 1、5 节与验证要点；第三方登录与公开注册的相关决策已于 2026-11-07 回退，
  见 ADR-0015（已废止）。

## 背景

此前后端 `mobile`、`dept_id`、`role_ids` 均为可选，前端未对部门与角色做必填校验，
且表单暴露「是否超管」开关。管理员可凭此直接创建出超管或管理员账号，形成越权通道。

新建 OA 用户还会联动创建钉钉通讯录成员，而钉钉侧创建必须要有手机号；
手机号留空会导致「OA 用户建成了，钉钉账号创建失败」的半截状态。

## 决策（用户逐条确认的 A1–A6）

### 1. 必填项

新增与编辑时，`mobile`、`dept_id`、`role_ids` 三项均为必填。

前端表单加必填规则，后端 schema 同步强制，**不能只靠前端隐藏或提示**。

**2026-11-06 补充作用范围**：必填只约束「管理员在后台新增 / 编辑」这一条主路径，
其它入口不靠放宽 schema 绕过，而是各自明确去向：

| 入口 | 处理 |
|---|---|
| 后台新增 / 编辑 | 保持必填（`mobile`、`dept_id`、`role_ids`） |
| `POST /system/user/register` 公开注册 | **已回退**：恢复框架原版自动建号；因必填 schema 仍在，该入口目前仍报校验错误，待统筹优化（见 ADR-0015 已废止） |
| Excel 导入 | 模板增加「角色」列（填角色名，空 = `USER`），手机号为空给明确行级错误；非超管导入不得指派管理员角色 |
| OAuth / 微信第三方登录 | **已回退**：恢复框架原版自动注册。真实需求是「用户自己绑定自己的微信等」，属首页改版 H1，已移交外部开发者；本项目不再保留「管理员后台绑定」（见 ADR-0015 已废止） |

### 2. 角色边界（双重限制）

- `is_superuser` 必须为 `false`；
- 角色只能是 `USER`，不允许出现 `ADMIN`、`SUPER_ADMIN`。

两条同时成立才算「普通用户」。仅挡 `is_superuser` 不足以限制权限，
因为 `ADMIN` 角色本身就带管理权限。

### 3. 作用范围

新增与编辑**都**受限。编辑时同样不允许把他人提升为管理员或超管。

### 4. 超管豁免

`is_superuser = true` 的账号不受上述任何限制，可创建、编辑任意角色的账号。
否则将没有任何入口再建管理员账号。

### 5. 管理员不能改动高权限账号（2026-11-06 扩大到全部写路径）

管理员（非超管）**不能编辑** `ADMIN` 或 `SUPER_ADMIN` 角色的账号，包括基础信息。
此类账号只能由超管维护。

**2026-11-06 修订**：保护范围从 `update()` 扩大到 `reset_password()`、
`set_available()`（停用 / 启用）、`delete()` 全部写路径，前端按钮同步禁用。
重置密码等于直接接管对方账号，停用 / 删除等于变相剥夺其管理权，三者与编辑同级，
没有理由只堵一条。`_assert_target_editable` 是统一入口。

另外：角色前置校验改走与 `_set_user_roles()` 同一套数据权限口径的 `RoleCRUD` 查询，
避免「先通过校验、写入时又报角色不存在」；软删用户复活时一并清理 `deleted_id`，
`username` 与 `mobile` 分别命中不同软删记录时给明确冲突错误，不再 `.first()` 复活错对象。

理由：若允许改基础信息，手机号被改会影响钉钉账号匹配，角色被改可直接降级他人权限。

### 6. 存量用户不动

不批量补齐历史数据的手机号、部门、角色，仅约束新增与编辑时的提交。

## 影响

- 前端：表单必填规则、超管开关的显隐、角色选项过滤、编辑按钮的可用性。
- 后端：schema 必填校验、service 层的角色与目标账号双重校验。
- 钉钉联动：手机号必填后，新建用户的钉钉创建不再因缺手机号而失败。
- 部门映射（`iac_account_dept_mapping`）仍需手工维护；部门未建映射时，
  OA 用户可建成，但钉钉侧创建会失败并提示。

## 验证要点

1. 管理员新增用户缺手机号 / 部门 / 角色 → 前端与后端均拒绝。
2. 管理员新增用户携带 `is_superuser=true` 或 ADMIN 角色 → 后端拒绝。
3. 管理员编辑 / 重置密码 / 停用 / 删除 ADMIN/SUPER_ADMIN 账号 → 后端一律拒绝，前端按钮禁用。
4. 超管新增 ADMIN 账号 → 允许。
5. （已废止）原「公开注册返回已关闭」不再作为验收项；现行状态见 ADR-0015 第三节。
6. （已废止）原「未绑定第三方提示先完成绑定」不再作为验收项；现行状态见 ADR-0015 第三节。
7. Excel 导入缺手机号 → 行级错误；角色列为空 → 默认 USER；非超管填 ADMIN → 拒绝。
8. 复活软删用户 → `deleted_id` 清空；用户名与手机号命中不同软删记录 → 明确冲突错误。
5. 存量无手机号用户不受影响。
