# 薪资计算与工资条规则

> 2026-11-01 建立。依据用户逐条确认的 A1–A6、B1–B4、C1–C4 及企业微信绩效登记补充。
> 2026-11-02 修订：取消定时和手动工资生成，改为全员绩效确认后自动生成。
> 2026-11-03 修订：每月 3 日处理上月考勤与绩效，改用钉钉单聊通知；零绩效员工免设置、免确认，详见 ADR-0012。
> 范围：内务中心「薪资绩效」第一期；只有存在考勤组的员工才参与薪酬计算。

## 一、薪资档案与第一期范围

每个 OA 用户一份独立薪资档案，包含：

- 基础工资：月度固定基准；
- 全勤奖：达到全勤条件时发放的金额；
- 补贴：固定月金额，不按出勤折算；
- 绩效基准：该员工每月绩效的预设金额，例如 2000 元。

第一期只计算：**折算基础工资＋全勤奖＋固定补贴＋实际绩效−缺卡扣款**。
考勤能够驱动的部分自动计算，绩效扣款按月人工登记。

社保、公积金、个税、提成、佣金均不在第一期展示或计算，只保留后续扩展空间。

## 二、计算公式

设某员工当月：

- 应出勤天数为 `R`，实际出勤天数为 `A`；实际出勤采用 ADR-0010 的自算口径，允许半天；
- 上班缺卡与下班缺卡次数之和为 `n`，同一天上下班都缺卡算 2 次；
- 当月绩效扣款为 `D`。

```
折算基础工资 = 基础工资 ÷ R × A
全勤奖实发   = A = R 时发全额全勤奖，否则为 0
实际绩效     = max(绩效基准 − D, 0)
缺卡扣款     = n × 10 × n = 10n²
实发工资     = 折算基础工资 + 全勤奖实发 + 固定补贴 + 实际绩效 − 缺卡扣款
```

### 全勤

只比较实际出勤与应出勤是否相等。例如应出勤 25、实际出勤 25 即全勤；
实际出勤 24.5 不算全勤。不再额外叠加「无迟到、无请假」等条件。

### 不重复扣款

基础工资已经按 `A ÷ R` 折算，所以旷工、事假、病假等少出勤造成的扣减已经包含在折算结果中，
**不得再额外收取旷工费、事假费或病假费**。迟到、早退第一期也不额外罚款。

缺卡扣款是独立的次数罚款：1 次扣 10 元，2 次扣 40 元，3 次扣 90 元。

### 绩效不为负

绩效基准按人设置，绩效扣款按月、按人登记。扣款高于基准时，实际绩效按 0 元，
不允许形成负绩效，也不能把超出部分转成其他扣款。

## 三、工资条持久化与生成

每位参与计算的员工每月形成一条工资条，保存当月使用的薪资档案数值、考勤数值、绩效扣款和计算结果，
不能只在打开页面时临时计算。

- 每月 3 日 00:00 拉取上月考勤；3 日 12:00 起，管理员未设置完绩效就每天通过钉钉单聊提醒；
- 3 日后管理员设置绩效时若上月无考勤，先自动补拉，成功后再保存；
- 绩效基准为 0 的员工免设置、免确认，实际绩效为 0，仍生成工资条；
- 有绩效奖金的员工即使扣款为 0，也要先设置、再确认；
- 全部设置完成后通知员工核对，管理员随后逐人确认；
- 最后一名应确认员工确认绩效后，立即自动计算并生成整月工资条；没有定时生成或手动生成入口；
- 工资条生成前可以撤销个人绩效确认并修改扣款；生成后绩效和金额全部固定，不能再次生成或重算；
- 超管确认工资条后，通过钉钉单聊通知该员工查收。

## 四、确认后永久锁定

工资条确认后永久锁定，**任何人都不能撤销确认或修改**，包括超级管理员和管理员。
确认前必须完成核对；确认动作需要明确提示其不可逆性。

这条规则有意放弃「确认后发现错误再撤销」的能力，优先保证已确认工资条的严肃性和不可变性。

## 五、权限边界

| 能力 | 普通员工 | 管理员 | 超级管理员 |
|---|---|---|---|
| 查看自己的考勤月报、日明细、工资条 | 可以 | 可以 | 可以 |
| 查看所有人的考勤和工资条 | 不可以 | 可以 | 可以 |
| 修改基础工资、全勤奖、补贴、绩效基准 | 不可以 | 只读 | 可以 |
| 在工资条生成前登记、修改每月绩效扣款 | 不可以 | 可以 | 可以 |
| 确认或撤销个人绩效（仅限工资条生成前） | 不可以 | 可以 | 可以 |
| 确认工资条 | 不可以 | 不可以 | 可以 |
| 撤销已确认工资条 | 不可以 | 不可以 | 不可以 |
| 手动拉取考勤、安排公司休息日 | 不显示 | 管理侧能力 | 管理侧能力 |

普通员工页面不出现任何管理按钮，也不能通过直连接口读取他人数据；数据限制必须由后端执行。

## 六、被否掉的方案

- **只实时计算、不保存工资条**：历史结果会随考勤或薪资档案变化，无法作为稳定凭证；
- **基础工资固定全发，再单独扣请假和旷工**：规则分散，且容易重复扣款；
- **全勤要求无迟到、无请假**：用户明确只要求实际出勤等于应出勤；
- **缺卡按次线性扣款**：用户明确采用 `10n²`；
- **绩效允许扣成负数**：用户明确绩效最低为 0；
- **确认后允许超级管理员撤销**：用户明确任何人都不能撤销；
- **每月 8 日定时生成或管理员手动生成工资条**：2026-11-02 取消，统一由全员绩效确认触发；
- **只在 8 日提醒一次**：未生成时 8、9、10 日持续提醒，避免遗漏；
- **第一期纳入社保、公积金、个税、提成、佣金**：全部留待后续阶段。

## 七、绩效登记与生成的衔接

每月 3 日 12 点起使用钉钉单聊提醒管理员设置上月绩效；未设置完则每天 12 点继续提醒。
全部设置完成后先通知员工核对，管理员再确认。管理员可以修改月度绩效扣款并逐人确认，
但不能修改员工的绩效基准或其他薪资档案；这些仍只有超级管理员能改。

绩效确认与工资生成在同一个事务中完成。最后一名应确认员工确认时，系统重新核对范围，
全部一致才生成整月工资条。零绩效员工自动满足设置和确认条件。生成后不允许再次生成，
绩效扣款和计算快照均固定。超管最终确认后才通知员工工资已发放。

## 八、与既有 ADR 的关系

- 考勤只包含有考勤组的员工，沿用 ADR-0008；
- 公司休息日会影响应出勤、实际出勤等计算基数，沿用 ADR-0009；
- 实际出勤不含请假、允许半天，沿用 ADR-0010；
- 本 ADR 不修改钉钉原始数据，也不改变考勤月报本身的计算规则。

## 九、实施记录（2026-11-01）

- 新增 `app/plugin/module_internal/salary/`，包含薪资档案、月度绩效扣款、工资条三张表及独立 `/internal/salary/*` 接口；未修改框架文件。
- 金额使用 `Numeric(14,2)` 与 `Decimal` 计算，四舍五入保留两位小数；工资条保存全部计算快照。
- 任务注册脚本为 `scripts/insert_salary_jobs.py`。2026-11-02 起每月 8–10 日 11:30 未生成则提醒，旧版 12:00 定时工资生成任务已停用。
- 企业微信机器人复用插件层 `wecom_bot.py`，从 `WECOM_WEBHOOK_URL` / `WECOM_WEBHOOK_SECRET` 环境变量读取配置；未配置或发送失败不阻断工资生成。
- 菜单脚本新增 `salary-attendance:manage` 与 `salary-performance:manage`；`sync_employee_salary_access.py` 只向 USER 授予两个 query 权限。
- 考勤月报、日明细与工资条均在后端按 `oa_user_id` 限制员工本人数据，管理员通过 manage 权限查看全部；薪资档案修改和工资条确认额外校验 `is_superuser`。
- 实测：以 2026-09 真实考勤和 5000 基础工资、200 全勤奖、300 补贴、2000 绩效基准、500 绩效扣款生成，应出勤 25、实出勤 23、缺卡 2 次，折算基础工资 4600、实际绩效 1500、缺卡扣款 40、实发 6360；重复生成、绩效锁定、员工越权访问均被拦截。测试事务已回滚。
- 后端 `compileall`、前端 `pnpm ts:check` 均通过，薪资及考勤接口 HTTP 冒烟通过。

## 十、全员绩效确认流程实施（2026-11-02）

- 删除 `/payslip/generate` 和 `/payslip/generation-state`，页面不再显示手动生成按钮。
- 全员确认进度按当月考勤月报范围计算；最后一人确认立即生成，生成的工资条仍为「未确认」，等待超管最终确认。
- 实测一名员工时确认进度为 1/1，自动生成 1 条实发 6360 元的工资条；生成后撤销绩效被拦截，提醒停止，超管最终确认正常。
- 手动考勤补拉同步调整为每月 7 日 00:00 后开放，规则记录在 ADR-0008。
- 后续修复：绩效列表增加 `attendance_ready`，当月无考勤月报时确认按钮禁用，后端确认接口同样拒绝；
  草稿登记不受限制。2026-10 员工丁误确认记录已按用户决定备份后清除。
- 后端编译、前端类型检查通过；所有测试写入均已回滚。
