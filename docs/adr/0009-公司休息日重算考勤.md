# 公司休息日重算考勤

在考勤组原有规则之上，允许公司按「日期 + 考勤组」临时安排额外休息日（不用打卡、不用上班），
由 OA 侧记规则并**自己重算**应出勤 / 休息 / 旷工等月报数字，同时给考勤明细的「考勤结果」列上色。

> 2026-10-30 建立，结论来自一轮 grill（A1–A8 + A6 收口）。
> **本条打破了 ADR-0002**「考勤结果以钉钉智能月报为准，本系统不重新统计」——
> 当某月存在公司休息日时，OA 会以钉钉月报为基准、叠加休息日规则重新计算。
>
> 2026-11-06 修订（缺陷复核 BUG-05，用户 A6 拍板）：原 A5 假设「审批文本里带当天请假量」，
> 与钉钉实况不符。真实文本是**整单**起止时间 + 整单总量（如
> `病假09-02 13:00到09-02 17:30 0.5天`），跨天假单在覆盖的每一天重复同一条文本。
> 因此「剔除休息日文本再聚合」会让剩余工作日仍按整单计一次全量，休息日等于没扣。
> 改为「全月整单聚合 − 休息日占比」：按起止时间把整单量折到每天（边界日按上午/下午折
> 0.5 天、中午整天 1 天，与声明总量对齐后按比例缩放兜底），文本解析不出起止时间时
> 按该单实际出现的日期平均拆分。无休息日时结果与原聚合一致，重算保持幂等。
>
> 2026-11-06 再修订：公司休息日改为按「考勤组方案」分叉处理。本文第二、三节的
> 规则表只适用于「休息」方案；「补工资」方案完全不改考勤统计，见第八节。
> 本次修订不新增决策编号，避免与本文既有的编号混淆。

## 一、为什么不让钉钉自己重算

最初设想是「给考勤组加几天休息日，让钉钉重算」。调研后这条路走不通：

- 考勤组甲 考勤组是 `type=FIXED`（固定班制），而钉钉按日期临时排班的接口
  `topapi/attendance/group/schedule/async` 文档明确要求考勤组为**排班制（TURN）**，固定班制用不了；
- 固定班制的「特殊日期」只在**创建**考勤组的接口里出现，更新接口的参数列表没有它；
- 改考勤组还要额外申请「考勤组管理权限」。

所以改为 **OA 侧记规则、自己重算**，钉钉只提供原始月报作为基准。

## 二、锁定的决策（A1–A8）

> 适用范围：本节与第三节的规则表只描述「休息」方案（ADR-0014 的 `mode: 1`）。
> 「补工资」方案与未配置的组不走这套规则，见第八节。

| 编号 | 决策 | 结论 |
|---|---|---|
| A1 | 休息日粒度 | 按「**日期 + 考勤组**」，组里全员一起休 |
| A2 | 生效时机 | 登记 / 删除后**立即重算**当月已同步数据；未同步的月份在每月 3 日 00:00 同步时自动套用（2026-11-03 起，原为 7 号） |
| A3 | 钉钉判「旷工」的休息日 | 改判休息：应出勤 −1、休息 +1、旷工 −1 |
| A4 | 钉钉判「正常」的休息日 | 算上班：应出勤 −1（**全组统一减**），出勤照算、不加休息 |
| A5 | 钉钉判「病假/事假/迟到/缺卡」等的休息日 | 一律改判休息，对应请假 / 异常清零 |
| A6 | 明细原文 | 显示「公司休息」，但**底层保留钉钉原文**（可反悔、可对账） |
| A7 | 月报休息天数 | **合并进现有休息列**，不单开列 |
| A8 | 配色 | 假期黄、休息绿、旷工红；公司休息与钉钉休息同色绿；正常 / 缺卡 / 外勤不上色 |

A4 用户原话：「休息日如果出勤都算出勤，但整个月的需要出勤日是相同的，
不会因为他多出勤一天，他的应出勤日就比别人多。」—— 应出勤对全组统一，
来上班的人出勤照算（白赚），不应出勤日因人而异。

## 三、重算规则表（按钉钉原文类别）

新增一个休息日 D，先取该人 D 这天的钉钉原文 `raw_text` 归类，再按下表调整月报：

| 钉钉原文类别 | 应出勤 | 出勤 | 休息 | 旷工 | 请假 | 迟到/早退/缺卡计数 | 明细显示 |
|---|---|---|---|---|---|---|---|
| 休息（本就是钉钉休息日） | 0 | 0 | 0 | 0 | 0 | 0 | 休息（不动） |
| 正常 / 外勤（干净上班了） | −1 | 0 | 0 | 0 | 0 | 0 | 公司休息（A4） |
| 旷工 | −1 | 0 | +1 | −1 | 0 | 0 | 公司休息（A3） |
| 病假 / 事假 / 年假 | −1 | 0 | +1 | 0 | −该日占比 | 0 | 公司休息（A5） |
| 迟到 / 早退 / 缺卡（来了但有异常） | −1 | −1 | +1 | 0 | 0 | −1 | 公司休息（A5） |

说明：

- 「本就是钉钉休息日」不产生任何调整（应出勤本来就没含这天），只是防御性兜底；
- 「迟到/早退/缺卡」这天人来了（钉钉记了出勤），但用户拍板「算休息」——
  这天按休息处理，出勤 −1、异常计数清零、休息 +1（与 A4 的「正常」区别对待是用户明确的）；
- 请假量是浮点（如 0.5 天）。**不能再「只聚合非休息日的审批文本」**：跨天假单每天
  重复同一条整单文本，剔掉休息日那天后，剩余工作日仍会把整单计一次全量（BUG-05）。
  现在按整单起止时间推导每天占比，从全月整单总量里减去落在休息日的那部分。

删除休息日 = 反向操作，把当天按同一规则**还原**回钉钉原值（这正是 A6 要留原文的原因）。

## 四、数据模型

| 改动 | 说明 |
|---|---|
| 新表 `iac_attendance_rest_day` | `group_id + rest_date` 唯一 + `month`（冗余便于按月查）+ `remark`；**物理删**（纯配置，删了重加即可） |
| 日明细加 `effective_text` | 展示值，默认 = `raw_text`，公司休息日 → 「公司休息」。`raw_text`（钉钉原文）**永不动** |
| 月报加 `dingtalk_raw`（JSON） | 同步时写入一次的钉钉原始月值快照，是重算的基准 |

**为什么留 `raw_text` + `dingtalk_raw`**：重算 = 「基准 + 休息日调整」，可逆的前提是基准还在。
`raw_text` 是日粒度基准，`dingtalk_raw` 是月粒度基准。两者都不被重算覆盖，
所以增删休息日可以反复重算而不漂移（幂等），删除也能精确还原。

`dingtalk_raw` 为 NULL 的历史行（本功能上线前同步的），首次重算时先把当前列值当作基准回填
（那时还没有休息日，列值就是钉钉原值），之后再重算都以回填后的快照为准。

## 五、同步流程的接入

`sync_month` 末尾追加一步：拉完钉钉落库后，若当月已存在休息日，对该月跑一次重算。
这样「3 日 00:00 先同步、之后才登记休息日」和「先登记、3 日 00:00 才同步」两种顺序结果一致（A2；2026-11-03 起按 ADR-0012 执行，原写 7 号）。

## 六、被否掉的方案

| 方案 | 为什么没采用 |
|---|---|
| 让钉钉重算（改考勤组 / 临时排班） | 固定班制无排班接口，见第一节 |
| 软删休息日 | 纯配置，删了重加即可；物理删让 `(group_id, rest_date)` 唯一约束干净不冲突 |
| 月报按 delta 增量改、不留基准 | 反复增删会漂移；留 `dingtalk_raw` 基准后幂等全量重算更稳 |
| 出勤天数从日明细文本反推 | 钉钉「出勤天数」口径无法从 raw_text 可靠反推（出勤 ≠ 简单的类别计数），故用快照基准 |

## 七、代价与边界

- **应出勤口径变了**：有休息日的月份，应出勤是「钉钉应出勤 − 休息日中本是工作日的天数」，
  不再是纯钉钉值。导出 / 薪资绩效若引用应出勤，拿到的就是重算后的值（这正是需求目的）。
- **统计依赖日明细文本归类**：重算靠 `raw_text` 归类（旷工 / 正常 / 请假…），
  钉钉若改文案（如「休息」改成别的词），归类会失准。归类表集中在 service 一处，改文案只动那里。
- **无日明细行的休息日**：某人在休息日 D 没有日明细行（如月中入职），该人该天跳过调整并记日志。

## 八、按考勤组方案分叉（2026-11-06 修订）

方案配置在后端 env 的 `INTERNAL_REST_DAY_POLICY` 里，按钉钉考勤组 ID 区分，
格式与校验见 ADR-0014 第三节。`recalc_month()` 先按 `group_id` 取方案，
**只把「休息」方案的日期放进 `rest_by_group`**：

| 方案 | 应出勤 | 异常计数 | 请假聚合 | 日明细展示 | 补贴 |
|---|---|---|---|---|---|
| 休息（`mode: 1`） | 按第三节规则表减 | 按规则表清 | 扣休息日占比 | 显示「公司休息」 | 无 |
| 补工资（`mode: 2`） | 不减 | 不清 | 不扣，按普通工作日全量聚合 | 保留钉钉原文 | 薪资侧按当天原文逐天判定 |
| 未配置 | 不减 | 不清 | 不扣 | 保留钉钉原文 | 无，等同没有公司休息日 |

原因：「补工资」那天员工照常上班，若仍按休息日处理，会一边减应出勤、清异常、
把落在那天的请假量扣掉，一边又发补贴 —— 请假的人会被算成正常出勤，还照样拿钱。
现在该方案不进入重算，`actual_days = 应出勤 − 旷工 − 请假` 按钉钉原值推导，
请假 / 旷工那天出勤自然少一天；补贴由薪资侧按当天钉钉原文逐天判定（见 ADR-0014）。

配套约束：

- 登记公司休息日前先校验方案，没配置该 `group_id` 直接拒绝并提示
  「该考勤组未配置休息日方案，请先配置再使用！」，不写孤儿配置。
- 生成工资条不依赖方案配置、不报警；未配置的组按「没有公司休息日」算工资。
- 已生成、已确认的月份不回溯。历史 `group_name` 为空或名称快照不一致的休息日行
  不再影响金额匹配（新链路只认 `group_id`），但历史工资条不重算。
- 改 env 配置需重启后端；配置文件由管理员自行维护。

回归测试：`backend/tests/module_internal/test_rest_day_mode_policy.py`。

## 九、2026-11-11 补记：A4「应出勤对全组统一」在薪资侧落地

A4 原话「整个月的需要出勤日是相同的……不会因为他多出勤一天，他的应出勤日就比别人多」
此前只落实在 `_apply_rest_day()` 的「全组统一减 1」，**月报里的 `required_days` 本身仍是
钉钉按人按天累加的个人列值，从未在组内对齐**。2026-10 暴露后果：同组正常员工 R=23，
11 号入职的新人（`oa_user_id=10`）R=9（11–13 上班没打卡、14–20 不在该考勤组打卡，钉钉只返回 9 天），
`A` 又被 ADR-0010 用同一个 R 推导成 9，`A/R = 1` → 新人拿整月全额工资。

本轮在**薪资侧**补上 A4（ADR-0011 第十一节）：`generate_month()` 按 `group_id` 取当月
应出勤的众数作为全组标准，只在个人值**低于**标准时抬平；正常员工、以及本 ADR
第三节公司休息日重算产生的合法差异一律不动（只抬不压）。`sync_month()`、
`recalc_month()`、`_apply_rest_day()` 的规则表、`raw_text` / `dingtalk_raw` 快照全部不改；
第七节「无日明细行的休息日跳过调整并记日志」的边界继续有效。
回归测试：`backend/tests/module_internal/test_new_hire_proration.py`。
