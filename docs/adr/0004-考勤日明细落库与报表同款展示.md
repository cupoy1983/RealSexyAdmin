# ADR-0004：考勤日明细落库，表统一 IAC_ 前缀

- 状态：已接受（2026-10-28）
- 相关：ADR-0002（考勤结果以钉钉智能月报为准）

## 背景

钉钉后台导出的月报 Excel 有 48 列，结构是「前缀列 + 10 个统计列 + 3 个假种列 + **按天铺开的 30 列考勤结果**」。
此前系统只存了月汇总，页面缺少「考勤结果」那一段，用户对照 Excel 时会发现对不上。

另外一个问题：`internal_` 前缀和 FineAdmin 其它模块（`sys_`/`task_`/`ecommerce_`）混在一起，
内务中心（Internal Affairs Center）的表不好辨认。

## 决策

1. **日明细落库**：新增 `iac_attendance_daily_report`，一行 = Excel 的一个日期格，
   唯一键 `(oa_user_id, work_date)`。
   - 不做 `day_1..day_31` 宽表：每月天数不同、跨月统计写不出 group by、加字段要回填历史数据。
   - 不做结构化状态字段（`day_status`）：钉钉的判定已经写在 `raw_text` 原文里，
     OA 侧再归类一次可能与钉钉自己的统计列对不上；等需要筛选/色块时再补。
   - 预留 `late_minutes` / `early_minutes` / `check_in_at` / `check_out_at` / `is_workday`，**当前不写值**。
2. **表前缀统一为 `iac_`**：`iac_account_binding`、`iac_account_dept_mapping`、
   `iac_attendance_monthly_report`、`iac_attendance_daily_report`。
   趁这几张表还没有数据一次改干净。
3. **工号 / 考勤组放在钉钉绑定表上**：`iac_account_binding` 增加 `job_number`、
   `group_id`、`group_name`、`dingtalk_dept_name`，每次月报同步时顺带刷新。
   月报再把这些值存成**当月快照**（员工后来改名/换组不影响历史报表）。
4. **部门名取钉钉部门名**：通过「部门映射」保证钉钉部门名与 OA 部门名一致；
   没配映射时退回 OA 部门名，不让这一列空着。
5. **页面**：不新增菜单、不做导出 Excel。月报表每行一个「查看明细」按钮，弹出该员工当月的日明细清单。

## 数据来源

仍然只用钉钉智能考勤报表的两个接口，不用打卡流水算考勤：

- `getattcolumns` 定位列 ID（10 个统计列 + 考勤结果 + 关联的审批单）
- `getcolumnval` 取整月「日粒度」值（一次最多 20 列，分批请求）

工号取 `topapi/v2/user/get` 的 `job_number`；考勤组取 `topapi/attendance/getusergroup` 的
`group_id` / `name`。这两个接口实测 errcode=0，**无需额外申请权限**。

## 请假算法（不变）

钉钉列定义里「事假 / 病假 / 年假」三列的 `id` 为 `None`（只是「请假」分组的表头），
`getcolumnval` 取不到，因此仍从「关联的审批单」文案按正则提取，
并按**整条文案**去重——跨天假同一张假条会在每一天重复出现，不去重会把 4 天算成 16 天。
用真实导出数据验证过：某员工病假 1 天 = 9-02 的 0.5 天 + 9-16 的 0.5 天。

## 后果

- 同步一次要写的行数变多（人数 × 天数），但数据量很小（几十人 × 30 天），可接受。
- 查询日明细按 `(oa_user_id, month)` 走索引，弹窗只查一个人一个月。
- 旧表 `internal_*` 已无数据，迁移后直接删除，不做兼容。
