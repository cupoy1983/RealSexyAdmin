# Excel 表头行由业务侧解析器自动定位，不改框架的 `ExcelUtil`

同一张「销售统计分析-按订单商品明细(系统)」报表，快麦有两种版式：**旧导出第 1 行就是表头**（35 列，`9月数据.xlsx` 实测），**新导出第 1 行是报表标题、第 2 行才是表头**（36 列 = 旧 35 列 + 新增「订单标签」，插在 `订单状态` 与 `订单状态(明细)` 之间，`12345.xlsx` 实测）。

而 `app/utils/excel_util.py:21` 把表头**写死在第 1 行**（`next(ws.iter_rows(min_row=1, max_row=1))`）。拿标题行当列名后，36 个格子内容相同 → 字典塌成一个键 → 必需列全丢。2026-10-28 走真实解析路径实测确认：**这份文件今天完全导不进来**，报的是

```
导入文件缺少必要的列: 订单商品明细ID, 系统订单号, 店铺编码, 店铺全称, 店铺平台, 订单状态, 主商家编码(款), 规格商家编码(SKU), 商品标题(款), 订单买家已付金额
```

这句话把人指向**完全错误的方向**（列其实都在，只是错位了一行），所以不能靠"让用户删掉标题行"来收口——那是一次记不住就会踩的坑。

## 决定

**订单与账单两侧各自的读取入口改成"自动定位表头行"**：从文件开头往下扫，**第一行同时含该侧必需列名**的行就是表头，它上面的行全部丢弃；从这一行起按现有逻辑取值。~~定位不到 → 保留现在这句「导入文件缺少必要的列」，但它是**扫过前若干行之后**才报的，文案本身因此重新变成准确的。~~（这句已被下面的 AF7 修订推翻：定位不到时它其实退回了「第 1 行是表头」，那句话因此仍然指错方向。）

## 为什么不直接改框架的 `ExcelUtil`

ADR-0019 与本项目一贯的约定是**只做业务代码、不动基础框架**。`read_excel_to_dicts` 现在被系统模块的导入导出共用，把它的表头定位从"第 1 行"改成"猜一行"，影响面远超电商：任何一份第一行恰好含关键字的普通表格都会被改变解释。业务侧要的是"快麦这两种版式都能吃"，不是"全仓库所有 Excel 都自动找表头"。

因此定位逻辑落在**电商插件内部**——`module_ecommerce/common/excel_head.py`（`common/` 的准入声明见 ADR-0035：电商多个子域共用、且不是外部系统对接的代码才进这里，订单与账单两家共用恰好符合）。`ExcelUtil.aread_excel_to_dicts` 保持原样、也**不再被电商调用**：表头定位与逐行建键必须是同一把尺子（空格处理、`strip()` 口径都要一致），拆成两处就会各说各话，所以 `excel_head.py` 是一条自包含的读取路径，只把 `ExcelUtil` 的行构建规则（`data_only=True`、整行全空跳过）照抄过来。

## 代价

- **多扫前几行**：每份文件多一次极小的遍历，成本可忽略。
- **"必需列名"成了新的隐式配置**：订单侧用 `订单商品明细ID` + `系统订单号`，账单侧用规则里配的运单号/账单日期列名。~~快麦哪天把列名改了，报错还是那句「缺少必要的列」~~——这跟 §5.1「必要表头含主商家编码(款)」（Z4/AA6①）已经是同一种脆弱处，不新增类别，只多一处；但**报的话**自 AF7 起换成「前 N 行找不到表头行，去核对这两个列名」，不再让人去文件里找根本不缺的列。
- **标题行含列名的误判**：理论上若某行既含标题文本又含必需列名会被错当表头。实测的快麦标题行 36 格全是同一句报表名，不可能命中必需列名，因此不做额外排除。

> **定位不到时不许冒充「第 1 行是表头」（2026-10-29 决议 AF7，设计文档 §20.5，修订上面「决定」末句与「代价」第二条）。** 上面那句「定位不到 → 保留『缺少必要的列』，文案因此重新变成准确的」是**错的**：定位不到时实现退回「第 1 行是表头」，而第 1 行往往是报表标题或说明文字，于是「账单文件缺少必要的列: 运单号(xxx)、账单日期(yyy)…」会把规则里配的五个列名全报一遍——**这些列可能好好地躺在第 11 行或第 2 行**，错的是规则里那两个探针列名配错了、或表头就在扫描窗口之外。这句话把人推向「快递给的表不对」，而真正该查的是「解析规则管理」里那两格。
>
> 改法：`read_excel_with_header_scan` 如实多返回一个「定位到了没有」，两个调用方据此说两句不同的话——**定位不到** → 报「前 N 行里找不到同时含 X、Y 的表头行」，并点名该去哪里核对（账单侧点名解析规则的两个列名，订单侧点名「这可能不是快麦订单导出」，因为它的探针列名是代码里硬编码的）；**定位到了但仍少列** → 才说原来那句「缺少必要的列」。空文件仍由各调用方自己的「文件为空」文案先接住：那份文件确实没有表头行，说「找不到表头」同样是误导。
