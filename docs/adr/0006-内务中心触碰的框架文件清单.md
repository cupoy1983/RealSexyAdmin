# 内务中心触碰的框架文件清单与批准记录

框架的硬约定是「只做业务代码、不碰框架文件」；实在躲不开时**必须单独报批**，并在 ADR 里留档。
本条记录内务中心（`module_internal`）这套功能在 RealSexyAdmin 侧对框架文件的全部改动 ——
哪些留下来了、哪些改过又撤回、以及撤掉之后的代价。

> 2026-10-29 建立。起因是有 6 处框架文件改动未经逐条报批就已落在工作区里，用户逐条复核后：
> 保留 5 处，撤回 3 处（其中 `sys_user.mobile` 的唯一索引一度同时改了模型与数据库）。
> 下面「已批准保留」的每一行都经过用户明确点头，不要再动；「已撤回」的行是踩过的坑，别再走一遍。
> 2026-10-29 追加：`user/service.py` 的 `delete()` 加钉钉离职联动（业务决策见 ADR-0007），
> 单独报批后实施。这是唯一一处会写钉钉的方法，改动面比 create/update 两处都大。
> 同日下午用户逐条拍板「A 手机号不能重复 / B bug 要修复」，本条清单据此定稿；

## 一、已批准保留（5 处）

| 文件 | 改动 | 为什么躲不开 |
|---|---|---|
| `app/config/setting.py` | 新增 `DINGTALK_APP_KEY` / `DINGTALK_APP_SECRET` / `DINGTALK_AGENT_ID` / `DINGTALK_ACCESS_TOKEN_CACHE_TTL` 四项（13 行） | 配置统一收在 `Settings` 单例里是全仓惯例（框架自己的 `WX_MINI_*` 也是这个写法）。可用「插件内自建 `BaseSettings`」替代，代价是配置分散两处，用户权衡后选择保留集中式 |
| `app/common/enums.py` | `RedisInitKeyConfig.DINGTALK_ACCESS_TOKEN`（1 行） | access_token 缓存键要在 Redis 初始化时登记。与 ADR-0001 里 Admin 那两条 Redis 键名同性质，那边也是单独批准后保留 |
| `app/modules/system/user/service.py` | create 加手机号必填 + 唯一校验、撞到已软删记录则复活（`_revive_soft_deleted_user`）；update 后同步钉钉成员手机号；delete 前预检并逐个办钉钉离职；多处函数内 `import` 调内务中心 Service | 新建/改手机号/删除三个动作的钉钉联动接入点。框架没有事件订阅这类扩展点，不动这里等于砍掉功能。复活逻辑是必须的：软删的行仍占唯一索引，让它撞库会把整条 INSERT 吐进响应体。函数内延迟 import 是为了避免 `modules` 反向依赖 `plugin` 造成启动期循环导入 |
| `frontend/.../fa-form/index.vue` | `defineModel` 对象默认值改工厂函数（1 行） | 真 bug：非工厂函数会让所有表单实例共享同一个 `{}` 引用，跨表单数据污染 |
| `frontend/.../fa-search-bar/index.vue` | 同上（1 行） | 同上 |

**同文件里不属于本条记录的东西**：`app/config/setting.py` 的 `ALLOWED_HOSTS` 被改成
`admin.realsxy.com` + `localhost`，那是用户自己的部署配置改动，与本条无关，不要顺手还原。

## 一-A、2026-11-05 追加（ADR-0013 用户必填与角色边界）

用户逐条确认 A1–A6 后实施，三处框架文件改动：

| 文件 | 改动 | 为什么躲不开 |
|---|---|---|
| `app/modules/system/user/schema.py` | `UserCreateSchema` 的 `mobile` / `dept_id` / `role_ids` 改为必填 | 约束必须在 schema 层生效，否则只在 service 判空会漏掉直接调接口的情况 |
| `app/modules/system/user/service.py` | 新增 `_assert_operator_scope` / `_assert_target_editable`，create 与 update 接入 | 角色边界必须落在写路径上。原有 `if data.is_superuser: raise` 是**无差别拦截**，超管也被挡，与「超管豁免」冲突，一并修正 |
| `app/modules/system/role/crud.py` | `get_options` 返回结构加 `code` | 前端要按角色编码过滤可选项，原结构只有 value/label，无法区分 ADMIN |

`role/crud.py` 属增量改动：所有用到角色选项的地方只是多一个 `code` 字段，不破坏既有结构。

验证方式：`tests/_tmp_user_scope.py`（一次性脚本，跑完已删）七项全过，含「非超管指派 ADMIN 被拒」
「非超管勾超管被拒」「空角色被拒」「USER 放行」「超管豁免」「编辑超管账号被拒」。
首次跑出 FAIL 是因为 `RoleCRUD.get_list(search={"id": ("in", ids)})` 未命中，已改为直接
`select(RoleModel).where(RoleModel.id.in_(...))`，不依赖 CRUD 的 search 语义。

## 二、已撤回（3 处，改过又退回框架原版）

| 文件 | 曾经改了什么 | 为什么撤 |
|---|---|---|
| `app/modules/system/user/model.py` | `mobile` 加 `unique=True` | 这是唯一一处改动了**框架表结构**的。撤回后唯一性由 `service.py` 的应用层校验兜底 |
| `app/api/v1/routers.py` | 3 行防呆注释（提醒别在这儿重复挂 `/internal`） | 纯注释，用户选择不留 |
| `app/__init__.py` | 4 行注释（说明考勤同步为何不注册 APScheduler 任务） | 纯注释，用户选择不留 |

撤回 `model.py` 的那条留下一个**代码与数据库不一致**的状态，必须记住：

- 数据库 `sys_user` 上有一个名为 `mobile` 的**唯一索引**，但它**不在任何 Alembic 迁移里** ——
  是早期手工 `ALTER` 加的，所以 `alembic history` 查不到它。
- 用户明确要求「手机号不能重复」，因此这个索引**保留不动**。
- 后果：ORM 模型声明的是普通索引，数据库实际是唯一约束。将来 `alembic revision --autogenerate`
  会想把它删掉，看到这个 diff 别盲目接受。

## 三、剩余风险（不动框架就修不掉，只留档）

`app/core/base_crud.py` 把数据库异常原样抛给客户端：

```python
raise CustomException(msg=f"创建失败: {e!s}")   # :218
raise CustomException(msg=f"更新失败: {e!s}")   # :256
```

响应体里会带出完整 SQL 语句、绑定参数与真实数据值（Admin 那边在
`docs/ecommerce-profit-phase1-design.md:15.9` 有同样的留档）。属框架文件，按硬约定不动。
业务侧能做的是**别去撞它**：

- create 路径：`service.py` 先 `get(mobile=mobile)` 校验；撞到**已软删**的记录走 `_revive_soft_deleted_user`
  复活（`username` / `mobile` 任一命中即可），撞到**未软删**的才报「已存在」。都不会撞库。
- update 路径：框架原版 `service.py:135-138` 本来就有手机号唯一校验，也不撞。
- 唯一剩下的口子是**并发竞态**：两个请求同时改成同一个手机号，应用层校验都通过、数据库拒绝。
  新建/修改用户是低频操作，接受这个概率。

> 2026-10-29 订正：一度判断「update 路径缺手机号校验，需要补一条」。这是错的 ——
> 框架原版 `user/service.py:135-138` 就有这段校验。撤回那条改动建议，未新增任何代码。

## 四、合并到 RealSexyAdmin 时注意

上面 5 处全部落在 Admin 也在持续演进的文件里，合并时会变成冲突点。处理顺序：

1. `setting.py`、`enums.py` —— 纯增量，直接把行搬过去，冲突好解。
2. `user/service.py` —— 唯一有行为改动的一处，要确认 Admin 侧 `UserService.create/update`
   在此期间有没有改过签名或加了别的校验，别覆盖掉。
3. `sys_user.mobile` 的唯一索引 —— **不会被任何迁移带过去**，新库要单独建。
   建议照 `app/plugin/module_internal/scripts/` 里幂等脚本的写法补一个建索引脚本，别再手工 ALTER。
