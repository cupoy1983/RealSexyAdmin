# 本仓保持与上游 FastApiAdmin 可同步：上游自带文件一字不动

> 状态：已采纳（2026-11-13）

2026-11-13 用户两句口径把这件事定死了：

> 「**这个是框架的文档，我们是在框架的基础上修改和增加功能，后续可能还要从框架的代码仓库拉取他更新的代码的。**」
> 「**非 plugin 的文件修改都是经过我同意的，以后要合并也是我主导的。**」

要判的原问题是治理队列第 ② 条：`REQUIREMENTS.md` 这类上游基线文档要 **留** / **改名标清"上游"** / **删**。

## 量到的事实（全部只读）

| 文件 | 行数 | 内容 | 全仓真被提到 |
|---|---|---|---|
| `REQUIREMENTS.md` | 3135 | 标题即「SaaS 多租户平台需求文档」，讲平台架构与数据隔离模型 | 5 处 / 4 个文件 |
| `SKILL.md` | 178 | 「FastapiAdmin 全栈开发指南」：工程地图、常用命令、前后端约定 | 2 处 |
| `CONTRIBUTING.md` | 49 | 上游的贡献流程与本地环境 | 8 处 |
| `CHANGELOG.md` | 25 | 停在 `[3.0.0] - 2026-08-10`，我们之后几十笔一条没记 | 4 处 |

- 四份在两个 clone 之间 **sha256 完全一致**（`docs/agents/shared-rules.md` §3.3 实测），即两边都还是上游那个样子。
- 统一化以来我们自己那一批提交（`b354d0e9`…`3241630e`）**一份都没碰过它们**：`git log -- <这四份>` 最新一笔仍是上游带来的 `24589ad9`。
- 本地只配了 `origin`（业务方的 fork），**没有配 upstream 远端**——"和上游差多少"现在根本量不出来，要说同步代价只能靠人不靠工具。
- 误读风险不是假想：上一轮就有 agent 把 `REQUIREMENTS.md` 当需求来源判过一次，靠 `AGENTS.md` 那句"不是我们的需求"才纠正回来。

## 决定

1. **上游自带的文件保持一字不差**：不搬、不改名、不删，四份基线文档首当其冲。三条候选里选「留」，理由是同步成本，不是信息价值——搬进 `docs/upstream/` 或删除都会让未来的 `git merge <上游>` 报 rename／delete 冲突，而信息本身在 git 历史里跑不掉。
2. **业务代码只放 `backend/app/plugin/module_<域>/`**（前端同理）。这不是审美，是为了同步：框架目录零改动 → 上游一动我们就是一条干净的 merge。`ADR-0040` 选"加一个空合并点"而不是"改框架里写死 `"head"` 的四处"，是同一个理由的第二笔收益。
3. **同步由业务方主导**：什么时候拉、怎么合、已动过哪些框架文件（那些改动都经他同意），都由他掌握。agent **不主动** `merge`／`cherry-pick` 上游，也**不**为同步预先维护"我们改过哪些框架文件"的撞点清单——那会变成一个要长期喂的机制，而他只要一次人工判断。
4. **防误读的控制点从"放在哪儿"换成"规矩怎么写"**：`AGENTS.md` 新增「这仓是上游框架的 fork」一节，`shared-rules.md` §3.3 补上处置结论。这与 §3.4 处理敏感信息是同一个路子——不给 `pii.mjs` 加规则，控制点是 agent 不写。

## 代价（认下来的，不是修辞）

- **门口那 3135 行还在**。位置控制换成了规矩控制，就意味着它挡不住不看规矩的人；唯一的补强是 CI 管得住"改动"，管不住"误读"。
- `CHANGELOG.md` 会一直停在 `3.0.0`。**不许替它续账**——我们的变更史在 git 里，写进上游那个文件只会给每次同步添一笔冲突。
- 真到同步那一天是**人工活**：没有工具能提前告诉我们撞多少，这是明确放弃做撞点清单换来的。
