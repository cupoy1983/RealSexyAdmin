# ADR-0014：DY-仓库考勤组休息日补贴

- 状态：已确认，已实施并验证
- 日期：2026-11-05
- 范围：薪资绩效 → 工资条生成

## 背景

仓库岗位在**公司休息日**仍要上班，需要按天给补贴。
补贴挂在「考勤统计 → 休息日安排」上：每登记一天休息日，该组当月每人每天补 100 元。

## 决策（用户逐条确认的 A1–A4）

### 1. 不累加，按当月天数计算

补贴 = **该组当月休息日天数 × 100 元**。

不采用「每加一天就往档案上 +100」的累加写法：累加只涨不减，
跨月后金额会失控，且与当月真实天数对不上。

因此：加一天多 100，删一天少 100，始终等于当月实际天数对应金额。

### 2. 只进当月工资条，不进薪资档案

`iac_salary_profile.allowance`（固定补贴）保持手工设定值，**不被修改**。

补贴体现在 `iac_salary_payslip.allowance`（固定补贴快照）：
`工资条补贴 = 档案固定补贴 + 当月休息日天数 × 100`。

档案是底薪性质的配置，休息日补贴是当月发生额，分开才能对账。

### 3. 考勤组按名称精确匹配

仅当 `MonthlyReportModel.group_name == "DY-仓库"` 时计入。
其他考勤组不产生该项补贴。

注意：**考勤组改名会导致匹配失效**，改名时需同步调整常量。

### 4. 已生成的工资条不重算

补贴只在 `generate_month` 生成工资条时计算一次。
已生成、已确认的月份不回溯修改。

若休息日是在工资条生成之后才登记的，当月不会补，需要等下月或重建该月工资条。

## 实现位置

- `salary/service.py` 新增 `_rest_days_by_group(month)`：按 `group_name` 统计当月休息日天数
- `_calculate()` 增加 `rest_days` 参数，组名匹配时把 `天数 × 100` 加进 `allowance`
- `generate_month()` 生成前一次性取好各组天数，逐行传入

## 验证要点

1. DY-仓库组当月登记 2 天休息日 → 该组工资条补贴 = 档案值 + 200
2. 其他考勤组 → 补贴 = 档案值，不变
3. 删除 1 天休息日后重新生成 → 补贴相应减少
4. 档案 `allowance` 字段全程不变
5. 已生成月份调用 `generate_month` → 仍被 `month_generated` 拦截，不重复计算
