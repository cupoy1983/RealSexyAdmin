# 一个仓库一份规则：所有在这个仓库上干活的 agent 受同一套约束

> 状态：已采纳（2026-11-13）

2026-11-13 用户口径：

> 「**以后所有的 agent 都需要有相同的约定和约束，代码仓库就一个，大家一起开发不同的功能。**」

这一句把 `docs/agents/shared-rules.md` 原有的前提（"**两个** agent 共用"）扩大成一般规则：并行方不再固定是"电商这边 + 内务那边"两个检出，而是任意多个 agent 在**同一个远端同一条分支**上各做各的功能。

## 被否掉的旧状态（有案可查，不是假想）

规则各留一份本机副本，正是 2026-11-11 之前几天的样子：`.gitignore` 里那行 `AGENTS.md` 把规则文件挡在库外（Windows 下连 `agents.md` 一起挡，`git check-ignore -v` 实测命中），对面 clone 的 agent 拿到的仓库里一个字都没有，规则只能靠业务方转述。**那次转述失真的后果就是往公开历史里写进了真实姓名与手机号**（`shared-rules.md` §1.4 第 1 条、§3.4 背景）。所以"约定必须住在仓库里"不是整洁偏好，是有代价的教训。

同理被否：`AGENTS.local-backup.md` 这种本机备份当第二份真相——业务方 2026-11-13 已裁「仓库版为准」，那份只作本机运维笔记，不提交、日后由他本人删（§五 D2）。

## 决定

1. **规则只有一份，且必须在仓库里**。入口是 `AGENTS.md`，细则是 `docs/agents/*.md`；任何 agent 在这个 checkout 里干活都受同一套约束，不开本机分支版。
2. **"一起开发不同功能"要防的三种撞，各有机器防**：
   - **号撞** → **号由业务方配，agent 不自行发号**：他要给起止两个号并建好 `NNNN-占位.md` 空壳推上来，agent 只改那一份文件（`ADR-0042` 的 2026-11-20 修订节；此前的 `adr.mjs new`／`reserve` 已从工具里删掉，撞在"每个检出各有一个发放者"）。真撞上了仍由 `check` 的「重号即红」判红（§1.1）。
   - **结构撞**（两人各拉一条迁移链）→ 迁移历史只许一个 head，`scripts/alembic-heads.mjs` 是 CI 第 5 步（`ADR-0040`）。
   - **领土撞** → 业务代码只放 `backend/app/plugin/module_<域>/`，域要先进 `docs/adr/domains.json` 登记才有目录可放；`check` 第 4 条守 `backend/tests/live/<域>/` 与 `module_<域>/`（T6）。
3. **改约定本身是最高风险动作**：机制文件——`AGENTS.md`、`scripts/*.mjs`、`docs/agents/**`、`docs/adr/domains.json`、`.github/workflows/**`——动手前逐条点头（写进 `shared-rules.md` §4.3）。理由：一处改动会被所有 agent 同时采纳，也同时被它们各自复述出去。
4. **闸要每个 agent 自己跑**，不等转述：日常三条 + 动到迁移目录时第四条 + 提交前 `pii.mjs`。工具链从 `b354d0e9` 起在远端，谁 `git pull` 谁就有闸。

## 修订（2026-11-19）：第 2 条「号撞」补上跨检出那一半——号按块占位

> **本节的两条命令 `new` 与 `reserve` 已于次日删除，改判见下面 2026-11-20 那一节。** 本节原文照留，是为了记下当时为什么那样定；按它施工会撞上一条已经报错的命令。

业务方 2026-11-19 原话：

> 「**不是CI发号，我怎么保证同一个代码仓库，不同的开发人员adr不冲突，我要问的是这个。**」
> 「**每次要nextNumber的时候，你来问我，然后你每次取号多取几个……比如现在是42，那你就取43 44 45，下一次别人取号就是46-50，5和0作为节点。**」
> 「**对，就是先占位，哪怕是空的adr，先占位后写内容，可以吗？0 5 这样不仅好记，而且好控制。**」

**为什么原先那一行不够**：`nextNumber()` 只扫本地 `docs/adr/` 取 `max+1`，不联网、读不到对面 clone——两个从同一提交起的检出各自 `new`，必拿同一个号。**CI 也不发号，从来没发过**：workflow 从第一天起是 `permissions: contents: read`，五步无一步建 ADR（`git log -S "adr.mjs new"` 与 `git log -S "contents: write"` 本仓都是 0 命中）。

1. **改了什么**：那一行现在分成两半——同一检出内由 `new` 保证唯一；**跨检出靠"一个人分块"**：发号前先向业务方要一个对齐 0／5 的块尾，`node scripts/adr.mjs reserve <尾号>` 一次把整块建满空壳（`NNNN-占位.md`，状态写 `占位（日期）`），下一块从块尾 +1 起。
2. **`new` 的取号规则不变，但号段内禁止用它**：取号仍是 `max+1`；**块里还有未填占位时 `new` 直接报错拒绝**（退码 1，一个文件都不建），报错点出该改的那几份壳。**填占位是直接改那一份文件**（标题、状态、正文，号不动）；文件名里的「占位」换成 slug 属可选整理，索引取的是正文标题。
3. **一次建满，而不是只占头尾**：号段不许有洞是 `check` 第 1 条，只建壳的那几个号才占得住——中间留空号会让所有人的 `check` 一起判红。
4. **`check` 新增第 2b 条：引用不许指向状态还是「占位」的 ADR**。号占住了不等于决议存在，引用一份空壳就是把一个还没定的口径当已定。报错给两条出路：先把那份填了，或改写成「待 ADR-NNNN 落定」。占位自己标题里那一句不算引用（否则每份空壳一出生就红）。`index` 生成的「下一个号是 X」后面附带未填占位清单，对面 `pull` 之后一眼看得见哪几个号已被人占走。
5. **尾号对齐 0／5 由人报，工具不猜**：没对齐时 `reserve` 只打一行提醒，不判红——那是「好记也好控」，不是可机检的不变量。
6. **否掉的两种替代**：让 CI 发号（得给它写权限，而且"先提交再定号"与本仓「一次提交就是一次发布」的时序相反）；重建 `reserve_upto` 那类底账文件（2026-11-12 删过，下面「代价」一节原本也否掉了占用声明表——这次的差别是**占位的真相就是 ADR 文件自己**，没有第二本账要对齐）。
7. **仍然防不住的那一半**：`reserve` 不联网，两个人各喊「占到 45」照样撞。兜底是事后的三条——`check` 的重号即红、`index` 在 `README.md` 里一人一行必产生 Git 冲突、`git pull --ff-only` 拉不动就停下来问（`shared-rules.md` §1.5）。**防撞的主控制是人**（业务方错开报尾号），这一条与下面「代价」里那句"没有占用声明表"不冲突：这里占号的是 ADR 文件本身。这次占的那一块到本节收口时三份全是空壳，清单不写在这里（会过期），看生成物 `CONTEXT-MAP.md` 那句「未填占位」。要撤掉占位就直接删文件：洞只算到当前最大号，所以删顶上那几份不红，删中间那份才会。
8. **没有松动的是**：「永远不要手敲 ADR 号」「号由工具发、不回收」一字未改；本条另外两种撞——结构撞（`ADR-0040`）与领土撞（`domains.json` 登记）——照旧。
9. **块用尽即停**（业务方 2026-11-19：「43-45就给你用了，用完了问我要新的号段」）：手上没有块时**先向业务方要新块尾，不许自行 `new`**；`new` 只用于首次发号，**块内的 ADR 一律靠「填空壳」产生**，号不动。壳还没填完时工具拦得住（第 2 条 `new` 直接报错）；整块填完之后拦不住，靠这句话兜，真撞了由 `check` 重号判红。
10. **验收钉子**：`shared-rules.md` §1.1 表里有 `reserve` 那一行，外加「跨检出的号不是工具防的，是一个人分块防的」那一段；`docs/adr/` 里存在状态为「占位」的文件而 `check` 仍绿；引用一份没填的占位 → `check` 红，填掉后同样引用 → 绿；`reserve` 尾号没对齐 0/5 → 只提醒；**块里还有未填占位时 `new` 退码 1、一个文件都不建**。

## 修订（2026-11-20）：发号收归业务方——`new`、`reserve`、`renumber` 从工具里删掉

业务方 2026-11-20 原话：

> 「**起始点当然由我说，我都会告诉 agent**」
> 「**就按照我来和 agent 说 adr 的起始点来修改，删除 new reserve，修改 check 和 index**」
> 「**renumber 有什么用？没用了就删除**」
> 「**占位不推，46推了，看不见43-45也不报错。**」

**为什么上一节的机制要推翻**：`reserve` 只收一个尾号，**起点是它自己扫本地最大号 +1**（那份代码的 `start = max + 1`）。两个检出没互相 `pull` 过时，本地最大号都是 45——业务方就算把尾号错开到 50 和 55，两边也各自从 46 建起，**块照样重叠在 46–50 上**。上一节第 7 条只承认了"两个人各喊同一个尾号会撞"，实际更糟：连喊不同尾号也撞。而 `new` 只在"块里还有未填占位"时拦（第 2 条），整块填完就静默发号。两处合起来：**防撞的前提一直是"只有一个发放者"，而工具给了每个检出各一个发放者。**

1. **删了什么**：`adr.mjs` 的 `cmdNew`、`cmdReserve`、`cmdRenumber` 三个子命令整体删除，连带 `mkdirSync`（建文件的活没了）和 `nextNumber()`／`renameSync`（只有它们在用）也不再需要；分发处留一条**判红**——`adr.mjs new`／`reserve`／`renumber` 打到这三个词时退码 1，报错直接说"号由业务方配，去改那份 `NNNN-占位.md`"，不是静默"用法不明"。**`renumber` 同日一并删掉**：业务方先只点名删 `new`／`reserve`，我保留了它并说明"仍是 `max+1`"，他的口径是「**renumber 有什么用？没用了就删除**」。按这条判据它是没用的——它给的是「本地最大号 +1」而不是他报的那个号，留着就是仓库里最后一条自助定号的路。号真写错了的修法是手工的：照他报的号 `git mv` 文件名、改正文的 `# ADR-NNNN` 那行，再跑 `index`。`check` 与 `index` 一字未删，只改文案（见第 4 条）。
2. **新的口径**：要写一条决议 → 向业务方报需求，**他给起止两个号并建好 `NNNN-占位.md` 空壳**（这份壳推不推由他定，见第 3 条） → agent **直接改那一份文件的标题、状态、正文，号不动**。agent 手上没有任何能造出 ADR 文件的命令。
3. **占位允许不推，所以「号段有洞」降成提醒**（业务方 2026-11-20：「**占位不推，46推了，看不见43-45也不报错**」）。判红站不住的原因是本地分不出这两种洞：一种是**对面手上那块还没推上来**（合法），一种是**号敲错了或漏建了一份**（要拦）——`docs/adr/` 里少一份文件，两种情况长得一模一样。实测过（Temp 夹具：拿掉 0043–0045 三份壳、塞进一份已填的 0046）：判红的版本里，红的是**没拿到我那截壳的对面和 CI**，不是漏号的那一方。所以这条从 `errs` 挪进 `notices`，打印「号段有洞：… —— 占位可以不推，洞现在只提醒不判红」，退码 0。
   - **代价说清楚**：`new`／`reserve` 一删，「号段有洞」原本是抓手敲错号的**唯一**兜底；降成提醒后这个兜底没有了，CI 照样绿。46 敲成 47、漏建一份，只剩人眼和对面问一句。
   - **仍然判红的是**：重号、文件名与文件内的号不一致、引用指不到真实文件、区间裸尾号指不到、引用指向未填占位（第 2b 条）、引用带域名、测试目录未登记、相对链接断。
   - **号段连着配还是配号的口径**（下一块从上一块尾号 +1 起，中间不留空号），只是它现在是一句约定，不再由机器强制。
4. **`check` 与 `index` 各改了哪几句**：`check` 的「号段有洞」原文是「号由工具发放，不要手填；新 ADR 用 `adr.mjs new`」——那条命令已经不存在，改成第 3 条那句提醒；`index` 有两处把用法写进**生成物**（`docs/adr/README.md` 抬头一句、`CONTEXT-MAP.md` 末尾一句「下一个号是 X」），都改成"向业务方要号段"，并且不再预告 `max+1` 是哪个号——那正是 agent 以前拿去自助发号的依据。除第 3 条那一项降级之外，判断逻辑没动。
5. **没松动的是**：号全仓唯一、一条序列、平铺在 `docs/adr/`；引用只写 `ADR-<NNNN>` 不带域名；空壳即占位的真相（仍然没有第二本底账）；`check` 第 2b 条「引用不许指向未填占位」、CI 五步、`pii.mjs` 出场时机，全部照旧。上一节第 8 条那句「号由工具发、不回收」**这半句改了判**：号由**业务方**发、不回收——"不回收"没动。
6. **给兄弟检出（`../RealSexy-OA`）的提醒**：它 `pull` 之前手上的 `new`／`reserve` 还能用，那是旧版工具，**不算违判**；`pull` 之后第一次跑 `new` 会撞上一条判红，照报错改成本节第 2 条的流程即可。**别顺手把上一节（2026-11-19）那十条当过期内容清理掉**——它是这条改判的对照面，删了后来人就看不出为什么不用 `max+1`。
7. **验收钉子**：`adr.mjs check` 绿（本仓 0001–0045 无洞，所以那句提醒平时不出现）；`adr.mjs new 试一下`、`adr.mjs reserve 50`、`adr.mjs renumber docs/adr/0045-占位.md` 三条都退码 1、`docs/adr/` 一个文件都不多也不改名；**洞的那条用 Temp 夹具验**：把 `docs/adr` 与 `scripts/adr.mjs` 拷进一棵空目录、删掉三份壳再放一份已填的 0046，`check` 打印「提醒：号段有洞：0043–0045…」并且**退码 0**；`adr.mjs index` 跑完 `git diff --exit-code docs/adr/README.md CONTEXT-MAP.md` 为 0；`grep -rn "adr.mjs new" --include=*.md` 只剩历史句子。

## 修订（2026-11-19）：`pii.mjs` 删掉 `NAME_RATIO` 这一条规则

业务方 2026-11-19 原话：「**把这一条拦截全部删除。**」＋「**直接删除，修改 adr，不用新建 adr**」。

1. **删的是第 5 条规则 `NAME_RATIO`**（形状：中文标点 `、：:(（` 之一 → 2~3 个汉字 → 空格 → `数字/数字`），连带删掉 `--selftest` 里那条正向探针（不删它自检判失败）。闸现在是 **4 条规则 / 11 条探针（5 正向 + 6 反向）**。
2. **理由是它双向不可靠**，不是"它漏了什么"：同一句式在文档里响，在代码注释里因为不带中文标点而不响（`# 员工甲 23/17` 放行）；`（步骤 2/5）`、`（默认 1/3）` 这种与人名无关的分数照样响（误报）。§3.4 那句「误报一次，两个 agent 就会开始无视这个闸」反过来读就是这条规则的判决书。
3. **否掉的两种替代**：给它补反向探针（等于继续养一个形状启发式）、重开豁免底账（`pii-waivers.json` 已于 2026-11-12 删除，登记那条代码路径也一并拆掉了）。
4. **没有松动的是口径**：`NAME_PREDICATE` 继续抓 `user_name='张三'` 这类真名进代码；`shared-rules.md` §3.4 那条写作硬线一字未改——真实姓名仍不得写入代码与文档的任何位置，多人仍用员工甲／乙／丙。变的只有这一类**不再有机器兜底**，控制点回到「agent 不写」＋提交前拿本机值清单做完全匹配。
5. **连带记录**：`docs/agents/pii-inventory.md` 第 1、8 两格与末尾缺口表已改口径。删规则后 `docs/adr/0011-薪资计算与工资条规则.md:174` 那句「员工甲 23/17」自动合法，**文字未改，别当成漏改的脱敏任务**——这是对面 clone 的 agent 最可能误判的一处。
6. **验收钉子**：`node scripts/pii.mjs --selftest` 退码 0 且打印 `正向 5 / 反向 6`；`node scripts/pii.mjs` 全仓 0 命中。

## 代价 / 明确不做

- **没有"谁正在改哪个文件"的占用声明**。两个 agent 同时编辑同一份文件，仍然要靠 Git 冲突当场才发现。第一版故意不做：派活的人是业务方，机制化的占位表只会变成又一本没人维护的底账（`legacy-citations.json`、`pii-waivers.json` 两本底账都这么死过，§1.3）。
- **约定变更没有通知机制**，靠对面下次 `pull`。
- **规则只有一份 ≠ 自动生效**：`AGENTS.md` 靠 agent 读，CI 只能管住可机检的那五步。写作规矩（§3.4、`ADR-0041` 那条"不动上游文件"）仍然没有机器兜底。

## 验收钉子

- `git ls-files` 里 agent 规则入口只有 `AGENTS.md` 一份，根上没有 `agents.md` / `agents.zh-CN.md`。
- `shared-rules.md` §4.3 里那条机制文件清单存在，且包含 `AGENTS.md` 自己。
- `.github/workflows/docs-adr.yml` 五步齐全，本地四条命令与远端五步等价（§1.4）。
