# 一个仓库一份规则：所有在这个仓库上干活的 agent 受同一套约束

> 状态：已采纳（2026-11-13）

2026-11-13 用户口径：

> 「**以后所有的 agent 都需要有相同的约定和约束，代码仓库就一个，大家一起开发不同的功能。**」

这一句把 `docs/agents/shared-rules.md` 原有的前提（"**两个** agent 共用"）扩大成一般规则：并行方不再固定是"电商这边 + 内务那边"两个检出，而是任意多个 agent 在**同一个远端同一条分支**上各做各的功能。

## 被否掉的旧状态（有案可查，不是假想）

规则各留一份本机副本，正是 2026-11-11 之前几天的样子：`.gitignore` 里那行 `AGENTS.md` 把规则文件挡在库外（Windows 下连 `agents.md` 一起挡，`git check-ignore -v` 实测命中），对面 clone 的 agent 拿到的仓库里一个字都没有，规则只能靠业务方转述。**那次转述失真的后果就是往公开历史里写进了真实姓名与手机号**（`shared-rules.md` §1.4 第 1 条、§3.4 背景）。所以"约定必须住在仓库里"不是整洁偏好，是有代价的教训。

同理被否：`AGENTS.local-backup.md` 这种本机备份当第二份真相——业务方 2026-11-13 已裁「仓库版为准」，那份只作本机运维笔记，不提交、日后由他本人删（§五 D2）。

## 决定

1. **规则只有一份，且必须在仓库里**。入口是 `AGENTS.md`，细则是 `docs/agents/*.md`；任何 agent 在这个 checkout 里干活都受同一套约束，不开本机分支版。
2. **"一起开发不同功能"要防的三种撞，各有机器防**：
   - **号撞** → **号由业务方报，agent 不自行发号**：他报起止两个号，agent 照这两个号建 `NNNN-占位.md` 空壳、之后只改那一份文件（本条的 2026-11-20 修订节；`adr.mjs new`／`reserve`／`renumber` 已从工具里删掉，撞在"每个检出各有一个发放者"）。真撞上了仍由 `check` 的「重号即红」判红（§1.1）。
   - **结构撞**（两人各拉一条迁移链）→ 迁移历史只许一个 head，`scripts/alembic-heads.mjs` 是 CI 第 5 步（`ADR-0040`）。
   - **领土撞** → 业务代码只放 `backend/app/plugin/module_<域>/`，域要先进 `docs/adr/domains.json` 登记才有目录可放；`check` 第 4 条守 `backend/tests/live/<域>/` 与 `module_<域>/`（T6）。
3. **改约定本身是最高风险动作**：机制文件——`AGENTS.md`、`scripts/*.mjs`、`docs/agents/**`、`docs/adr/domains.json`、`.github/workflows/**`——动手前逐条点头（写进 `shared-rules.md` §4.3）。理由：一处改动会被所有 agent 同时采纳，也同时被它们各自复述出去。
4. **闸要每个 agent 自己跑**，不等转述：日常三条 + 动到迁移目录时第四条 + 提交前 `pii.mjs`。工具链从 `b354d0e9` 起在远端，谁 `git pull` 谁就有闸。

## 修订（2026-11-19）：第 2 条「号撞」补上跨检出那一半——号按块占位

> **本节的两条命令 `new` 与 `reserve` 已于次日删除，改判见下面 2026-11-20 那一节。** 本节原文照留，是为了记下当时为什么那样定；按它施工会撞上一条已经报错的命令。

业务方 2026-11-19 原话：

> 「**不是CI发号，我怎么保证同一个代码仓库，不同的开发人员adr不冲突，我要问的是这个。**」
> 「**每次要nextNumber的时候，你来问我，然后你每次取号多取几个……比如现在是42，那你就取43 44 45，下一次别人取号就是46-50，5和0作为节点。**」
> 「**对，就是先占位，哪怕是空的adr，先占位后写内容，可以吗？0 5 这样不仅好记，而且好控制。**」

**为什么原先那一行不够**：`nextNumber()` 只扫本地 `docs/adr/` 取 `max+1`，不联网、读不到对面 clone——两个从同一提交起的检出各自 `new`，必拿同一个号。**CI 也不发号，从来没发过**：workflow 从第一天起是 `permissions: contents: read`，五步无一步建 ADR（`git log -S "adr.mjs new"` 与 `git log -S "contents: write"` 本仓都是 0 命中）。

1. **改了什么**：那一行现在分成两半——同一检出内由 `new` 保证唯一；**跨检出靠"一个人分块"**：发号前先向业务方要一个对齐 0／5 的块尾，`node scripts/adr.mjs reserve <尾号>` 一次把整块建满空壳（`NNNN-占位.md`，状态写 `占位（日期）`），下一块从块尾 +1 起。
2. **`new` 的取号规则不变，但号段内禁止用它**：取号仍是 `max+1`；**块里还有未填占位时 `new` 直接报错拒绝**（命令当场报错，一个文件都不建），报错点出该改的那几份壳。**填占位是直接改那一份文件**（标题、状态、正文，号不动）；文件名里的「占位」换成 slug 属可选整理，索引取的是正文标题。
3. **一次建满，而不是只占头尾**：号段不许有洞是 `check` 第 1 条，只建壳的那几个号才占得住——中间留空号会让所有人的 `check` 一起判红。
4. **`check` 新增第 2b 条：引用不许指向状态还是「占位」的 ADR**。号占住了不等于决议存在，引用一份空壳就是把一个还没定的口径当已定。报错给两条出路：先把那份填了，或改写成「待 ADR-NNNN 落定」。占位自己标题里那一句不算引用（否则每份空壳一出生就红）。`index` 生成的「下一个号是 X」后面附带未填占位清单，对面 `pull` 之后一眼看得见哪几个号已被人占走。
5. **尾号对齐 0／5 由人报，工具不猜**：没对齐时 `reserve` 只打一行提醒，不判红——那是「好记也好控」，不是可机检的不变量。
6. **否掉的两种替代**：让 CI 发号（得给它写权限，而且"先提交再定号"与本仓「一次提交就是一次发布」的时序相反）；重建 `reserve_upto` 那类底账文件（2026-11-12 删过，下面「代价」一节原本也否掉了占用声明表——这次的差别是**占位的真相就是 ADR 文件自己**，没有第二本账要对齐）。
7. **仍然防不住的那一半**：`reserve` 不联网，两个人各喊「占到 45」照样撞。兜底是事后的三条——`check` 的重号即红、`index` 在 `README.md` 里一人一行必产生 Git 冲突、`git pull --ff-only` 拉不动就停下来问（`shared-rules.md` §1.5）。**防撞的主控制是人**（业务方错开报尾号），这一条与下面「代价」里那句"没有占用声明表"不冲突：这里占号的是 ADR 文件本身。这次占的那一块到本节收口时三份全是空壳，清单不写在这里（会过期），看生成物 `CONTEXT-MAP.md` 那句「未填占位」。要撤掉占位就直接删文件：洞只算到当前最大号，所以删顶上那几份不红，删中间那份才会。
8. **没有松动的是**：「永远不要手敲 ADR 号」「号由工具发、不回收」一字未改；本条另外两种撞——结构撞（`ADR-0040`）与领土撞（`domains.json` 登记）——照旧。
9. **块用尽即停**（业务方 2026-11-19：「43-45就给你用了，用完了问我要新的号段」）：手上没有块时**先向业务方要新块尾，不许自行 `new`**；`new` 只用于首次发号，**块内的 ADR 一律靠「填空壳」产生**，号不动。壳还没填完时工具拦得住（第 2 条 `new` 直接报错）；整块填完之后拦不住，靠这句话兜，真撞了由 `check` 重号判红。
10. **验收钉子**：`shared-rules.md` §1.1 表里有 `reserve` 那一行，外加「跨检出的号不是工具防的，是一个人分块防的」那一段；`docs/adr/` 里存在状态为「占位」的文件而 `check` 仍绿；引用一份没填的占位 → `check` 红，填掉后同样引用 → 绿；`reserve` 尾号没对齐 0/5 → 只提醒；**块里还有未填占位时 `new` 会被当场拦下、一个文件都不建**。

## 修订（2026-11-20）：发号收归业务方——`new`、`reserve`、`renumber` 从工具里删掉

业务方 2026-11-20 原话：

> 「**起始点当然由我说，我都会告诉 agent**」
> 「**就按照我来和 agent 说 adr 的起始点来修改，删除 new reserve，修改 check 和 index**」
> 「**renumber 有什么用？没用了就删除**」
> 「**占位不推，46推了，看不见43-45也不报错。**」
> 「**建壳应该是 agent 来建不是我手工建**」
> 「**占位的都不推，写进.gitignore**」

**为什么上一节的机制要推翻**：`reserve` 只收一个尾号，**起点是它自己扫本地最大号 +1**（那份代码的 `start = max + 1`）。两个检出没互相 `pull` 过时，本地最大号都是 45——业务方就算把尾号错开到 50 和 55，两边也各自从 46 建起，**块照样重叠在 46–50 上**。上一节第 7 条只承认了"两个人各喊同一个尾号会撞"，实际更糟：连喊不同尾号也撞。而 `new` 只在"块里还有未填占位"时拦（第 2 条），整块填完就静默发号。两处合起来：**防撞的前提一直是"只有一个发放者"，而工具给了每个检出各一个发放者。**

1. **删了什么**：`adr.mjs` 的 `cmdNew`、`cmdReserve`、`cmdRenumber` 三个子命令整体删除，连带 `mkdirSync`（建文件的活没了）和 `nextNumber()`／`renameSync`（只有它们在用）也不再需要。**分发处不为这三个词单独留话**（同日砍掉：业务方一句「那 `adr.mjs old`、`adr.mjs go` 也要留咯？」点破了它的冗余——没人会去打一个没人告诉过他的词，真打了，那段专门报错也只是把规矩重抄一遍）。现在只认 `check` 与 `index`，其余一律回同一句用法：「用法：`node scripts/adr.mjs check|index` —— 它只校验、只生成索引，暂时没有其他命令。」**报错只报用法，规矩住在文档里**（本条 + `shared-rules.md` §1.1 + `AGENTS.md`），他的判据是「为什么要写这么多没有用的？」。打 `new` 的结果没变：仍然当场拦下、`docs/adr/` 一个文件都不建。**`renumber` 同日一并删掉**：业务方先只点名删 `new`／`reserve`，我保留了它并说明"仍是 `max+1`"，他的口径是「**renumber 有什么用？没用了就删除**」。按这条判据它是没用的——它给的是「本地最大号 +1」而不是他报的那个号，留着就是仓库里最后一条自助定号的路。号真写错了的修法是手工的：照他报的号 `git mv` 文件名、改正文的 `# ADR-NNNN` 那行，再跑 `index`。`check` 与 `index` 一字未删，只改文案（见第 4 条）。
2. **新的口径**：要写一条决议 → 向业务方报需求，**他报起止两个号** → **agent 照这两个号建 `NNNN-占位.md` 空壳**（状态写 `占位（日期）`；这份壳推不推由他定，见第 3 条）→ 之后**直接改那一份文件的标题、状态、正文，号不动**。这一步叫**建壳**，不叫发号：号是他报的，agent 只是把它写成文件名与正文的 `# ADR-NNNN`，里面没有任何"下一个号"的计算——那正是 `new`／`reserve`／`renumber` 三条被删掉的原因，它们也仍然一律当场拦下。
3. **占位允许不推，所以「号段有洞」降成提醒**（业务方 2026-11-20：「**占位不推，46推了，看不见43-45也不报错**」）。判红站不住的原因是本地分不出这两种洞：一种是**对面手上那块还没推上来**（合法），一种是**号敲错了或漏建了一份**（要拦）——`docs/adr/` 里少一份文件，两种情况长得一模一样。实测过（Temp 夹具：拿掉 0043–0045 三份壳、塞进一份已填的 0046）：判红的版本里，红的是**没拿到我那截壳的对面和 CI**，不是漏号的那一方。所以这条从 `errs` 挪进 `notices`，打印「号段有洞：… —— 占位可以不推，洞现在只提醒不判红」，**不算错，CI 绿、可以提交**。
   - **代价说清楚**：`new`／`reserve` 一删，「号段有洞」原本是抓手敲错号的**唯一**兜底；降成提醒后这个兜底没有了，CI 照样绿。46 敲成 47、漏建一份，只剩人眼和对面问一句。
   - **仍然判红的是**：重号、文件名与文件内的号不一致、引用指不到真实文件、区间裸尾号指不到、引用指向未填占位（第 2b 条）、引用带域名、测试目录未登记、相对链接断。
   - **号段连着配还是配号的口径**（下一块从上一块尾号 +1 起，中间不留空号），只是它现在是一句约定，不再由机器强制。
4. **`check` 与 `index` 各改了哪几句**：`check` 的「号段有洞」原文是「号由工具发放，不要手填；新 ADR 用 `adr.mjs new`」——那条命令已经不存在，改成第 3 条那句提醒；`index` 有两处把用法写进**生成物**（`docs/adr/README.md` 抬头一句、`CONTEXT-MAP.md` 末尾一句「下一个号是 X」），都改成"向业务方要号段"，并且不再预告 `max+1` 是哪个号——那正是 agent 以前拿去自助发号的依据。除第 3 条那一项降级之外，判断逻辑没动。
5. **没松动的是**：号全仓唯一、一条序列、平铺在 `docs/adr/`；引用只写 `ADR-<NNNN>` 不带域名；空壳即占位的真相（仍然没有第二本底账）；`check` 第 2b 条「引用不许指向未填占位」、CI 五步、`pii.mjs` 出场时机，全部照旧。上一节第 8 条那句「号由工具发、不回收」**这半句改了判**：号由**业务方**发、不回收——"不回收"没动。
6. **给兄弟检出（`../RealSexy-OA`）的提醒**：它 `pull` 之前手上的 `new`／`reserve` 还能用，那是旧版工具，**不算违判**；`pull` 之后第一次跑 `new` 会撞上一条判红，照报错改成本节第 2 条的流程即可。**别顺手把上一节（2026-11-19）那十条当过期内容清理掉**——它是这条改判的对照面，删了后来人就看不出为什么不用 `max+1`。
7. **验收钉子**：`adr.mjs check` 绿（本仓 0001–0045 无洞，所以那句提醒平时不出现）；`adr.mjs new 试一下`、`adr.mjs reserve 50`、`adr.mjs renumber docs/adr/0045-占位.md` 三条都被当场拦下、`docs/adr/` 一个文件都不多也不改名；**洞的那条用 Temp 夹具验**：把 `docs/adr` 与 `scripts/adr.mjs` 拷进一棵空目录、删掉三份壳再放一份已填的 0046，`check` 打印「提醒：号段有洞：0043–0045…」并且**不算错，CI 绿、可以提交**；`adr.mjs index` 跑完再拿 `docs/adr/README.md` 与 `CONTEXT-MAP.md` 跟仓库里已提交的版本比对，**一模一样、没有差异**才算过（有差异就是生成物被手改了，或改完没重跑 `index`）；`grep -rn "adr.mjs new" --include=*.md` 只剩历史句子。
8. **同日再改判：空壳一律不进库**（业务方「**占位的都不推，写进.gitignore**」，随后「**库里躺着的撤出来**」）。上面第 2、3 条那句"推不推由他定／占位允许不推"**在这条收紧为一律不推**：`.gitignore` 加 `docs/adr/*-占位.md`，已经进库的 0043–0045 三份壳用 `git rm --cached` 撤出索引（文件留在本地，`git check-ignore -v` 实测命中 `.gitignore:100`）。壳的生死因此变成：**填成正式决议、改完名，那一刻才第一次 `git add`**。
   - **改名从"可选整理"变成必须**：忽略规则匹配的是**路径**，不看内容。一份填好了却仍叫 `0046-占位.md` 的决议照样被忽略，`git add` 收不进去（实测：`git check-ignore -v docs/adr/0046-占位.md` 命中，`docs/adr/0046-some-slug.md` 不命中）。而本仓规矩是不擅自 `git add -f`——所以**先把文件名里的「占位」换成 slug，再谈提交**，此前几处文档写它"可选"，那半句在本条改掉。
   - **本条还收窄了第 1 条那句手工修法**：第 1 条写「号真写错了 → 照他报的号 `git mv` 文件名」，壳不进库之后**没填的壳不在版本控制里**，`git mv` 直接报 `fatal: not under version control`（实测：拿一份临时未跟踪文件试过）——那一步改用普通 `mv`，只有已进库的决议才用 `git mv`。改正文的 `# ADR-NNNN` 那行与随后跑 `index` 两步不变。
   - **连带必须改的一处（不改就自己造假红灯）**：`index` 原本把未填的壳写进两份生成物——`docs/adr/README.md` 一人一行，`CONTEXT-MAP.md` 末尾那句「未填占位」后面跟着的三个号。壳不进库之后，那几行**本地有、CI 与对面没有**，CI 第 3 步 `git diff --exit-code docs/adr/README.md CONTEXT-MAP.md`（「生成物不许手改」）就会在谁都没手改过的情况下判红。所以 `cmdIndex` 现在把 `isPlaceholder` 那批滤掉，两份生成物只列已填好的决议；`CONTEXT-MAP.md` 的「当前最大号」也只数已填的，本仓因此从 0045 回到 0042。**`check` 不滤**——它读的本来就是本地文件系统，未填壳照样占号、照样被第 2b 条管着。那句提醒打印的措辞也从第 3 条的「占位可以不推」改成「空壳不进库，没填的那几号本来就看不见」——上面第 3、7 两条引的是**当时**那句话，别按现在的输出对不上就当文档写错。
   - **同一句引用在两边的报错不同**：引用一份只存在于我这个本地的空壳，这里 `check` 报第 2b 条「引用了还空着的占位 ADR-NNNN」；CI 与对面手上没有那份文件，同一句引用报成第 2 条「引用了不存在的一条 ADR-NNNN」。两条都判红，只是话不同——别把本地见过的那句当成 CI 会说的话。**新长出来的一条红路**：把 ADR 填好推上去、正文引用同块里还没填的号，本地绿（壳在）或红（指空壳），推上去一定红，因为对面根本没有那个文件。出路仍是第 2b 条那两条：先填，或改写成「待 ADR-NNNN 落定」。
   - **第 3 条的降级理由不变，只是变了默认**：洞本来就一直会出现——现在**任何**一块没填完的号段，在对面和 CI 眼里都是洞。判红照样只能冤枉人，所以那句提醒仍只打印不判红。
   - **`pii.mjs` 从此扫不到还叫「占位」的那份文件**：它的取文件口径是「tracked + 未跟踪且未被 ignore」（实测本次跑到的就是 1022 份），壳被 ignore 就落在范围外。**提交那道闸不受影响**——按上一条，进库前必须先改成 slug，改完名它就成了"未跟踪且未被 ignore"，照样进扫描。**但起草那一段是裸的**：往一份还没改名的壳里粘真实姓名／号码，没有任何机器看得见。口径不变（§3.4 那条"agent 不写"仍是主控制），只是这里从"有闸"变成"确实没有"。
   - **验收钉子（本条新增）**：本地留着 0043–0045 三份未填壳跑 `node scripts/adr.mjs index`，`docs/adr/README.md` 与 `CONTEXT-MAP.md` 里**不得**出现这三个号（实测：两份生成物的表里最后一行是 0042，`git diff` 的删除侧正好是那三行）；`git ls-files docs/adr | grep -c 占位` = **0**；同样三份文件在 `docs/adr/` 里存在（`ls` 得到），且 `git check-ignore -v` 命中 `.gitignore:100`。**对面视角实测（2026-11-20）**：把那三份壳临时挪出 `docs/adr/` 模拟 CI 的文件系统——`check` 绿，报 **42 条决策、961 处引用**，并且**没有**那句洞提醒（那边的最大号本来就是 0042，无洞可言）；`index` 重新生成的 `docs/adr/README.md` 与 `CONTEXT-MAP.md` 跟本地（壳在位时）**逐字节一致**（`diff` 空输出）——CI 第 3 步那道「生成物不许手改」因此不会被我这三个本地壳惹红。壳挪回来再跑，输出回到 45 条决策、964 处引用（差的 3 处正是三份壳自己标题里的那个号，同一文件内不算引用）。**上面那句「壳不进库之后引用怎么说」在本条写完时当场被第 2b 条拦下一次**（正文里写了 `ADR-` 加一个未填的号，`check` 报错拦下、这次提交不能过）——这就是第 2b 条活着的最直接证据。

## 修订（2026-11-21）：建壳的人复述两次号——报到我这边、建完报回你那边

业务方 2026-11-21 原话：

> 「**建完壳把文件名原文回读一句，例如「建了 0046-占位 … 0050-占位 共 5 份」可以**」

9. **加一条动作规矩，不是闸**：建壳**前后各复述一次号**——动手前把业务方报的那两个号原样回一遍（「收到 46–50，建 5 份」），建完把新建的文件名原文报回去（「建了 `0046-占位.md` … `0050-占位.md`，共 5 份」）。它补的正是上一节第 3 条自己写下的那句代价：`new`／`reserve` 一删、「号段有洞」降成提醒之后，agent 把号段建错没有任何机器看得见。这条不改工具、不加闸，只把号摊到业务方眼前一次，**而且是唯一还便宜的时点**——壳不进库，此刻改名／补建／删掉重来都不碰任何历史。
   - **抓得到这两种，都是批量动作本身的错**：范围展开漏一份（说 5 份，只建出 4 个文件——剩下那几号还是连着的，连「号段有洞」那句提醒都不响，纯静默）；文件名打字手滑（`0046` 敲成 `0056`、复制上一行忘改号——这种会把 max 顶高，提醒会打印一句，但提醒不拦提交）。**这里不写"记错号段"**：号在业务方那一句话里，建壳的人照抄，没有第二条路可走，把它当成一种失败模式是编的。
   - **抓不到的写清楚，别假装兜住了**：真撞号仍只靠 `check` 的重号即红（事后的）；**引用写成另一个已存在的号**（想引甲条，落笔成了乙条，两个号都真实存在）任何闸都看不见——第 2 条只问"引得到引不到真实文件"，两个号都在库里时它必然绿。所以这条规矩管的是**建出来的号**对不对，**引过去的号**对不对没有机器管，只能靠读那一句的人。
   - **验收钉子**：下次业务方报一块号，agent 的回话里那两个号各出现一次（动手前）、文件名清单出现一次（建完）；缺一句就是没照做。

## 代价 / 明确不做

- **没有"谁正在改哪个文件"的占用声明**。两个 agent 同时编辑同一份文件，仍然要靠 Git 冲突当场才发现。第一版故意不做：派活的人是业务方，机制化的占位表只会变成又一本没人维护的底账（`legacy-citations.json`、`pii-waivers.json` 两本底账都这么死过，§1.3）。
