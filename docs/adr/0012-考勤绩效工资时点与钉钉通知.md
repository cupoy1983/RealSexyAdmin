# 考勤、绩效、工资时点与钉钉通知

> 2026-11-03 建立。依据用户逐确认的新流程，取代 ADR-0008 中「每月 7 日拉考勤」及
> ADR-0011 中「每月 8–10 日企微提醒」的时点安排；薪资公式和工资条永久锁定规则不变。
> 本文是业务规则定稿，具体通知文案须另行取得用户确认后才可配置到程序中。

## 一、参与范围

- 只有存在钉钉考勤组的员工参与考勤同步和工资条生成，沿用 ADR-0008。
- 绩效基准大于 0 的员工，需要管理员按月设置绩效扣款；即使当月不扣款也要设置 0。
- **绩效基准等于 0 的员工视为无绩效奖金员工**：无需管理员设置或确认当月绩效，
  实际绩效固定为 0，仍参与考勤核对和工资条生成。
- 没有薪资档案不等于无绩效奖金员工，不能据此自动跳过。**应参与薪酬计算的人员必须存在未软删的薪资档案；缺任一人即阻止整月工资条生成，并报出缺档案名单**，不得按 0 元生成，也不得在考勤未拉全时生成。档案只要记录存在且未软删即为有效，绩效基准为 0 是合法值（零绩效员工仍免设置、免确认）。

## 二、每月处理时间线

以下均以「当前月份 M 处理上一个自然月 P」为例。例如 11 月处理 10 月。

| 时点 | 动作 |
|---|---|
| M 月 1–2 日 | 不允许设置 P 月绩效，不允许手动或自动补拉 P 月考勤 |
| M 月 3 日 00:00 | 自动拉取 P 月全员考勤；同月已经拉过则跳过 |
| M 月 3 日 12:00 | 若仍有需要设置的绩效，通过企业内部应用机器人私聊提醒管理员 |
| M 月 4 日起每日 12:00 | 只要 P 月仍有管理员未设置的绩效，继续提醒；全部设置完成即停止 |
| 管理员设置 P 月绩效时 | 若 P 月没有考勤数据，先自动拉取 P 月考勤，成功后再保存本次绩效 |
| 所有应设置绩效均完成 | 立即通过机器人私聊通知员工核对 P 月考勤与绩效 |
| 员工未提出异议 | 管理员逐人确认绩效 |
| 最后一名应确认员工确认绩效 | 自动生成整月工资条 |
| 超级管理员确认某员工工资条 | 通过机器人私聊通知该员工登录 OA 查看；工资条永久锁定 |

不设置强制员工核对期限。员工本期线下向管理员提出异议，不新增异议工单；
管理员尚未确认时可以修改，工资条生成后沿用锁定规则。

## 三、考勤补拉与失败

- 3 日 00:00 自动任务、3 日后的手动补拉、设置绩效时的自动补拉，全部只处理 P 月。
- 同一月份谁先成功拉取谁生效；库里已有 P 月考勤月报即视为拉取完成，不重复调用。
- 同步仍整批原子提交：任何一人失败则整批回滚，不留下半份数据。
- 设置绩效触发的补拉失败时，**不保存本次绩效**，将失败原因显示给管理员。
- 没有考勤组或没有可拉取人员时不能假装同步成功；此时管理员必须处理账号绑定／考勤组问题。
- 拉取考勤、保存绩效、发送通知是不同副作用：外部通知不得回滚数据库，
  但发送失败必须可见、可重试，不能静默当作已通知。

## 四、绩效设置与确认

- 管理员只处理绩效基准大于 0 且属于当月工资计算范围的员工。
- 「绩效设置完成」指所有这类员工已有当月绩效记录；零绩效员工自动满足，不进入待设置清单。
- 设置完成 ≠ 绩效确认。设置完成后先通知员工核对，管理员随后再逐人确认。
- 无绩效奖金员工自动视为已确认，不需要管理员多一次无意义点击。
- 全员应确认范围与工资条生成范围一致；最后一人确认后立即生成整月工资条。
- 工资条生成前可以撤销绩效确认或修改草稿；生成后不能撤销、重算或再次生成。

## 五、通知原则与接收人

1. 只使用已上线的**企业内部应用机器人单聊**，不使用群机器人发送工资或绩效相关内容。
2. 管理员提醒按「上月是否存在未完成绩效设置」触发，不固定只提醒三天。
3. 接收管理员由后端按薪资绩效 manage 权限筛选，并排除无可用钉钉绑定的人；
   发送结果需要记录，未绑定者不能导致已绑定者也收不到通知。
4. 员工通知只发给本人，不发送给主管、部门或群。
5. 钉钉消息不携带工资金额、绩效扣款金额或详细考勤数据，只提供月份和登录 OA 的指引。
6. 三类业务消息必须分别配置：
   - 管理员：待设置绩效提醒；
   - 员工：考勤与绩效核对提醒；
   - 员工：工资条最终确认后的查看提醒。
7. 钉钉单聊接口已在 2026-11-03 用员工甲账号实测成功；业务触发点和正式文案已按本 ADR 实施。

## 六、正式文案（用户已确认）

变量：`{name}` 为接收人姓名；`{month}` 为不带日的月份，例如「2026年10月」。

### N1 管理员绩效设置提醒

```text
亲爱的管理员 {name}，请登录 RealSexyAdmin，设置 {month} 员工绩效。设置完成后员工将收到考勤与绩效核对通知。麻烦了哦！
```

### N2 员工考勤与绩效核对提醒

```text
您好，{month} 考勤信息已登记，请登录 RealSexyAdmin 核对。如有异议，请及时联系管理员。
```

### N3 员工工资条查收提醒

```text
亲爱的 {name}，{month} 工资条已确认并发放工资，请注意查收！
```

## 七、不采用的方案

- **每月 7 日拉考勤、8–10 日企微提醒**：已被 3 日考勤与每日钉钉提醒替代。
- **绩效基准 0 也要求管理员登记和确认**：没有业务价值，已从待办中排除。
- **管理员设置绩效即自动生成工资条**：缺少员工核对与管理员确认环节，不采用。
- **绩效一确认就把工资条发给员工**：必须经过超级管理员最终确认。
- **在钉钉消息中直接写工资金额**：增加敏感数据扩散面，统一引导登录 OA 查看。

## 八、实施边界

- 本 ADR 已批准业务规则及第六节三类通知模板。
- 实施时优先修改 `module_internal`、插件侧钉钉客户端和对应任务注册脚本，
  不触碰 ADR-0006 清单中的框架文件。
- 需要清理或停用旧任务时，先核对数据库现有任务，避免同一提醒双渠道重复发送。

## 十、复核严重 3 修复（2026-11-08，用户 A1–A4 拍板）

- 根因：`requires_performance`、待设置／应确认名单把「无档案」与「零绩效」合并，待办分母为 0；每日任务不校验考勤即整批生成，缺档案按 0 元计算，生成后整月锁定。
- `generate_month()` 增加统一前置硬闸 `generation_blockers()`：先校验 `month_synced()`，再按当月应参与人员校验有效薪资档案；任一阻塞即整月不生成，异常消息带缺档案姓名与 ID 名单。两条自动路径（每日任务、最后一人确认）共用此闸。
- `process_daily_notifications()` 预检阻塞原因后跳过生成，返回 `blocked_reasons` 并写日志，避免异常回滚同事务的通知记录。
- 缺档案提示**只在绩效登记页展示**：状态列「未设薪资档案」＋页面告警列出名单，并写入后端生成错误消息与任务日志；不新增任何钉钉提醒，原有 N1／N2／N3 触发条件与文案不变。
- 绩效列表新增 `has_profile`；前端把无档案显示「未设薪资档案」并列出缺档案名单，不再显示「无绩效」。
- 存量工资条本轮不动数据；是否处置由生产只读盘点结果决定。

## 十一、2026-11-11 一次性数据订正破例（仅 2026-10 `oa_user_id=10` 一行）

第四节「生成后不能撤销、重算或再次生成」与 ADR-0011 第四节「确认后永久锁定」
**继续生效，代码与接口一律不放开**。系统没有工资条金额编辑接口
（`salary/controller.py` 无 update／edit／correct 路由），故本次缺陷只能直接改库，
属一次性破例，条件与范围严格限定：

- 只改 `iac_salary_payslip` 中 `month = '2026-10'` 且 `oa_user_id = 10` 的一行，
  字段只涉及 `required_days`／`actual_days`／`prorated_base`／`gross_amount`／`net_amount`；
- **仅在 `status = 0`（未确认）时执行**；若已被超管确认（`status = 1`）立即停止，不再订正
  （ADR-0018 锁定优先）；
- 由杜总本人在生产机手工执行，执行前整表 dump 备份、事务内 `UPDATE` 核对 `ROW_COUNT()=1` 才 `COMMIT`，另备单行回滚语句；该脚本属一次性运维操作，**不纳入版本库**（口径与验收见 ADR-0011 第十二节）；
- 不改考勤月报、不改 `dingtalk_raw`、不重跑生成、不回溯其他月份与其他员工；
- 该行仍为「未确认」，N3「工资已发放」通知按本 ADR 在超管确认后才发，本次订正不触发通知。

破例原因是新人入职当月被钉钉截短的分母导致全额发薪，口径与依据见 ADR-0011 第十一、十二节。
**不为它新增常规编辑能力**：破例只此一次，长期修复在代码侧（应出勤按全组统一）。
