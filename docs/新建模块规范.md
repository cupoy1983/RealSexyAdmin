# RealSexyAdmin 新建模块规范

本文件定义「在 RealSexyAdmin 里新增一个业务模块」的统一做法。
**新增模块前读一遍，收工后按第七节清单自检。**

> **证据来源**：2026-10-28 对 `RealSexyAdmin` 全仓扫描 —— 后端 67 个 controller、137 个权限串、
> 42 个前端页面、29 个 API 文件；并与 `RealSexy-OA` 的 `module_internal` 交叉核对。
> 所有条目都标注了「这是自研惯例」还是「这是框架自带，不要学」。

---

## 零、先分清：框架 vs 自研

写规范最常见的错误，是把脚手架的做法当成自己的规矩。**这个项目的边界是：**

| | 框架自带（不要学、不要改） | 自研（这是我们的规范） |
|---|---|---|
| 后端位置 | `app/modules/{system,monitor,task,ai,generator,common}` | `app/plugin/module_<域>/` |
| 前端位置 | `views/module_system|monitor|task|ai|generator|example` | `views/module_<域>/` |
| 注册方式 | `app/api/v1/routers.py` 的 `DOMAIN_CONTROLLERS` **手写** | `discover.py` **自动发现** |
| 数据种子 | `backend/sql/*.json`，由 `initialize.py` 灌入 | 见「菜单」一节 |

`app/plugin/infra/` 是基础设施（HTTP 客户端、各系统 `*Client`），不是模块，不带 `module_` 前缀。
`app/plugin/module_example/` 是 discover 的最小样例，**新模块直接照抄它**。

## 一、后端

### 1.1 目录骨架

```
app/plugin/module_<域>/
├── __init__.py                  ← 必须有
├── <业务A>/
│   ├── __init__.py              ← 每级都要有
│   ├── controller.py
│   ├── crud.py    model.py    schema.py    service.py     ← 五件套齐全
│   └── <辅助包>/                ← 只能被 service 引用，controller 不许用
├── common/
│   ├── __init__.py
│   ├── excel_head.py            ← 顶层只放共享工具，不是业务单元
│   └── <业务B>/                 ← common 下的业务单元同样要五件套
└── deploy/
    └── menu_dict_seed.sql       ← 菜单/权限的核对副本（见 1.6）
```

**`discover.py` 只扫描 `module_*/**/controller.py`** —— 没有 `controller.py` 的目录不会被 import，
所以 `deploy/` 这类目录不强制 `__init__.py`。但**从 `module_xxx` 到 `controller.py` 的每一级都必须有**，
少一个就 `ModuleNotFoundError`，而 discover 会因单个模块失败而**中止整个应用启动**。

### 1.2 路由

```
app/plugin/module_xxx/a_b/controller.py
   APIRouter(prefix="/a-b")      ← URL 用中划线
   ↓ discover：module_xxx → /xxx
/xxx/a-b
   ↓ servers.url = /api/v1
/api/v1/xxx/a-b                  ← 对外实际路径
```

- **一个 controller.py 可以定义多个 router**（自研才有，框架侧 26 个 controller 全是 1 个）：
  `store/controller.py` 里就是 `StoreRouter(prefix="/store")` 和 `TagRouter(prefix="/tag")` 并列。
  同一个页面的多个 Tab 业务放在一个文件里是**被鼓励**的做法。
- **绝不**在 `app/api/v1/routers.py` 里挂自己 —— 重复挂载会被 `check_route_conflicts` 判冲突并中止启动。
- 搬迁目录**不会改变对外 URL**，前缀由 discover 从目录名推导，与位置无关。

### 1.3 接口路径：扁平，不嵌套容器

证据：`/ecommerce` 域下 7 个接口，**全部是 2 级**：

```
/ecommerce/store   /ecommerce/tag          ← store 页面的两个 Tab
/ecommerce/order   /ecommerce/sku-cost     ← order 页面的两个 Tab
/ecommerce/logistics  /ecommerce/bill-parse-rule
/ecommerce/batch
```

没有任何一处是 `/ecommerce/<容器>/<子业务>`。更强的一条：**后端的 `sku-cost` controller 放在
`order/` 目录下，但它的路径是 `/ecommerce/sku-cost` 而不是 `/ecommerce/order/sku-cost`** ——
接口既不跟页面容器走，也不跟后端目录走，**只跟业务实体走**。

### 1.4 权限串

格式 `module_<域>:<资源>:<动作>`，全库 137 个权限串无一例外。

- **资源名用下划线**：`sku_cost`、`bill_parse_rule`、`login_log`、`dict_type`
- **URL 用中划线**：`/ecommerce/sku-cost`、`/ecommerce/bill-parse-rule`
- ⚠️ **这两个是反的，最容易写错**，见第三节对照表
- 动词词表：核心 `query / detail / create / update / delete / patch`；
  扩展 `import / export / download / upload / permission / execute / operate / sync / confirm / declare / task / scheduler`
- 例外（框架侧才有，别学）：`module_task:cronjob:job:*` 这类 4 段式

### 1.5 分层写法

```python
# model.py —— 业务表
class XxxModel(ModelMixin, UserMixin):        # from app.core.base_model
    __tablename__ = "<域>_xxx"
    ...
# model.py —— 纯关联表（无审计字段需求）
class XxxRelModel(MappedBase):
    ...

# crud.py
class XxxCRUD(CRUDBase[XxxModel, XxxCreateSchema, XxxUpdateSchema]):  # from app.core.base_crud
    def __init__(self, auth: AuthSchema, db: AsyncSession) -> None: ...

# service.py —— 一个文件可含多个资源类（StoreService + TagService 并列，实证存在）
class XxxService:
    def __init__(self, auth: AuthSchema, db: AsyncSession, redis: Redis | None = None) -> None: ...
```

- **表名前缀 = 域简名**：`ecommerce_*` / `sys_*` / `task_*` / `gen_*`
- **统一方法名**：分页 `page(page_no, page_size, search, order_by)`；其余 `detail(id) / create(data) / update(id, data) / delete(ids: list[int])`
- **controller 只 import 自己模块的 `.schema` 和 `.service`**；`parsers/`、`importers/` 这类辅助包由 service 引用

### 1.6 菜单：老实说这里两边不一致

| | RealSexyAdmin 现在的做法 | RealSexy-OA 的做法 |
|---|---|---|
| 来源 | 手工走管理界面录入 | 幂等脚本 `scripts/sync_<域>_menu.py` |
| 凭证 | `deploy/menu_dict_seed.sql`，注释写明「只是核对/补录副本」 | 脚本即真相来源 |

`initialize.py` 以 `sys_menu` 是否存在做哨兵，**改 `sql/sys_menu.json` 对已初始化的库完全无效**。
Admin 的 `sys_menu.json` 里根本没有电商菜单，就是这么来的。

**推荐做法是 OA 这套**（脚本可重复执行、可迁移、可授权）。新模块请写幂等脚本，并注意：
- 迁移旧节点时把**按钮节点也放进授权清单** —— 只在按钮上定义的权限，漏了就永远没人能拿到
- 脚本要处理「同名重复节点」和「角色授权迁移」，避免改造后有人点开一片空白

## 二、前端

### 2.1 页面组织

```
views/module_<域>/
├── <菜单项>/
│   ├── index.vue                 ← Tab 壳
│   └── components/
│       ├── AaaTab.vue
│       └── BbbTab.vue
api/module_<域>/
└── <菜单项>.ts                   ← 一个页面一个 ts
```

全 views 共 42 个页面，其中 28 个是单文件（67%）、14 个拆了子目录（33%）。
**自研电商模块 3 个页面 100% 用「Index 壳 + components/*Tab.vue」** —— 这是我们的标准做法，
框架页不是（它们连 Tab 内容都不拆，`module_system/log` 1200 行还是单文件）。

Tab 壳的标准写法：

```vue
<template>
  <div class="fa-full-height">
    <ElTabs v-model="activeTab" class="fa-tabs-fill">
      <ElTabPane label="店铺" name="store">
        <StoreTab v-if="activeTab === 'store'" />
      </ElTabPane>
    </ElTabs>
  </div>
</template>
```

- **Tab 内容惰性渲染**（`v-if="activeTab === 'xxx'"`），进页面只加载当前 Tab
- **`ElCard class="fa-table-card"` 放在 Tab 子组件内部**，不要把 Card 包在 ElTabs 外面
  （全仓只有 `module_system/params` 是外层包 Card，那是框架页）

### 2.2 API 层

```ts
// api/module_xxx/<菜单项>.ts —— 一个页面一个 ts，内部并列多个 *_API_PATH
const STORE_API_PATH = "/ecommerce/store";   // ← STORE_ 前缀，与 Tab 对应
const TAG_API_PATH = "/ecommerce/tag";
```

- **一个 ts 多个常量**是标准做法：`store.ts` / `order.ts` / `logistics.ts` 各含 2 个
- 常量名用「业务名大写 + `_API_PATH`」，路径本身用 kebab
- 调用与取数：`await XxxAPI.page(q)` → `res.data.data.items`（`types/global.d.ts`：`{code, data, msg, status_code, success}`）

### 2.3 复用共用组件（别手写）

| 需求 | 用这个 | 别这样 |
|---|---|---|
| 分页 | `<FaPagination>`（`components/tables/fa-pagination/`） | 手写 `ElPagination` + 自造 `.fa-pagination` 样式 |
| 表格 | `<FaTable>`（`components/tables/fa-table/`） | — |
| 搜索区 | Admin 用 `<FaSearchBar>` | 手写 `ElForm` + 自造 `.fa-search-form` 样式 |
| 空状态 | `.fa-empty-state` 样式类 | — |

⚠️ **`fa-search-form` / `fa-pagination` / `fa-tab-toolbar` 这三个类在两个项目的 `styles/` 里都没有定义**，
它们是各个 vue 文件里 `<style scoped>` 自造的。只有这三个是全局真货：

```scss
.fa-full-height   // styles/core/_app.scss:134  撑满内容区高度，配合 box 布局
.fa-table-card    // _app.scss:84               表格卡独立滚动
.fa-tabs-fill     // _app.scss:107-130          让 ElTabs 在 flex 容器里撑满高度
```

### 2.4 命名与权限

```ts
defineOptions({ name: "Ecommerce<域>", inheritAttrs: false });   // Admin 自研统一前缀
defineOptions({ name: "Ecommerce<域><Tab>Tab" });                // Tab 子组件
```

```vue
<ElButton v-hasPerm="['module_ecommerce:store:create']">新增</ElButton>
```

`v-hasPerm` 取**数组**；函数版 `checkPerm(perm)`。`*:*:*` 为通配。

### 2.5 component_path 怎么变成组件

```ts
// router/MenuProcessor.ts:60-61
} else if ((item.component_path ?? "").trim()) {
    component = toComponentImportPath(item.component_path!);
// router/route-loader.ts:41
const lookupPaths = [`/src/views/${normalizedPath}`, `/src/views/${normalizedPath}.vue`];
```

即菜单的 `component_path = "module_xxx/store/index"` → `/src/views/module_xxx/store/index.vue`。
**找不到就渲染「[路由警告] 找不到组件」**，所以目录一定要对得上。

## 三、命名对照表（最容易写错的地方）

| 东西 | 分隔符 | 例子 |
|---|---|---|
| URL / controller prefix | **中划线** kebab | `/ecommerce/sku-cost`、`/bill-parse-rule`、`/internal/attendance` |
| 权限串的资源段 | **下划线** snake | `module_ecommerce:sku_cost:query`、`module_system:login_log:query` |
| Python 目录 / 文件名 | **下划线** snake | `module_ecommerce`、`sku_cost.py`、`bill_parse_rule` |
| ts 文件名 / 目录名 | **下划线** snake | `module_ecommerce`、`store.ts` |
| ts 里的常量名 | **大写下划线** | `STORE_API_PATH`、`BILL_PARSE_RULE_API_PATH` |
| Vue 组件名（`defineOptions.name`） | **驼峰** Pascal | `EcommerceStore`、`EcommerceBillParseRuleTab` |
| 表名前缀 | **下划线** snake | `ecommerce_store`、`iac_account_binding` |

**URL 和权限串是反的**：`/sku-cost`（中划线）配 `sku_cost:query`（下划线）。写之前回头看一眼这张表。

## 四、踩过的坑

### 1. 定时任务代码存在数据库里

`task_cornjob_node.func` 是**字符串**，里面写死了 Service 的 import 路径。模块搬家后改文件救不了它，
必须重跑注入脚本。这类任务通常几周才执行一次，**失败是静默的**。

### 2. 运行时 import 会被漏掉

函数内部的 `from ... import`（例如新建用户时联动钉钉那段）静态 grep 容易漏。
改完模块位置后，除了 grep `app\.modules\.` 这种绝对路径，还要 grep 短名 `module_<域>`。

### 3. 删旧目录会被 reload 抓到中间态

`ImportUtil.find_models` 会 os.walk 整个后端目录。搬运过程中新旧两份模型同时存在时：

```
Table 'xxx' is already defined for this MetaData instance
```

会被包成 CustomException **中止启动**。不是真故障：删完旧目录后 `touch` 一下触发 reload 即可恢复。
记住 **迁移过程中服务注定短暂不可用**，别误判成改坏了。

### 4. 菜单按钮漏出授权清单

身份认证回来：脚本若没把按钮节点放进授权清单，角色永远拿不到那个权限。
**只在按钮上定义**的权限尤其致命 —— 页面看着正常，功能全废。

### 5. 搜索表单的回车是哑的

`<ElForm @submit.prevent>` 后面不绑 handler，回车就是什么也不发生：
默认提交被拦了，但查询也没被调用，表格停在上一次结果上。
**必须写成 `@submit.prevent="loadData"`。** 正确参照 `views/module_ai/chat/components/FaAiModelConfigPanel.vue:177`。

### 6. 分页参数写成同级 Query 会让搜索条件静默失效（最隐蔽的一个）

`search: Annotated[XxxQueryParam, Query()]` **不是**"任何时候都展开成平铺字段"。FastAPI 的判据是
（`fastapi/dependencies/utils.py` 的 `_get_flat_fields_from_params`）：

```python
if len(fields) == 1 and lenient_issubclass(first_field.field_info.annotation, BaseModel):
    return get_cached_model_fields(first_field.field_info.annotation)   # 只有这时才展开
```

即：**同一个 dependant 的 query 参数恰好只有 1 个且是 BaseModel** 才展开。于是：

```python
# ❌ 同级还有两个 Query 标量 → 不展开 → ?month= 被丢弃，search 恒为 None
async def page(page_no: Annotated[int, Query(ge=1)] = 1,
               page_size: Annotated[int, Query(ge=1, le=200)] = 20,
               search: Annotated[XxxQueryParam, Query()] = None): ...

# ✅ 分页走 Depends()，进子 dependant，主 dependant 只剩 search → 展开生效
async def page(page: Annotated[PaginationQueryParam, Depends()],
               search: Annotated[XxxQueryParam, Query()] = None): ...
```

后果链：前端参数发出去了 → 后端 `search=None` → 不加任何过滤条件 → 返回全表。
**不报错、不告警**，表现为"换个条件查出来的还是同一批数据"。

两个排障要点：
- **openapi/swagger 看不出来**：框架自己的接口也把 `search` 显示成一个不透明参数，
  展开与否在文档上长得一样。只能用 TestClient / 真实 HTTP 实测。
- **别用"直接构造 QueryParam 对象调 service"来验证**——那绕过了参数解析，永远是对的，
  会得出"后端没问题"的错误结论。

`PaginationQueryParam` 的 `page_size` 上限是 100（不是 200），前端默认值别超过它。

## 五、已知例外（有意为之，不要"顺手纠正"）

| 例外 | 为什么 |
|---|---|
| OA 的表前缀是 `iac_` 不是 `internal_` | Internal Affairs Center 的缩写；`internal_` 与其它模块混在一起难辨认。这是 deliberate 的，见 ADR-0004 |
| OA 的前端目录仍叫 `module_internal` | `v-hasPerm`、动态路由、面包屑都引用它，改名波及远超一个目录 |
| `module_task:*` 是 4 段权限 | 框架自带域，历史如此，不迁移、不模仿 |
| `deploy/` 目录没有 `__init__.py` | 它不含 `controller.py`，discover 扫不到，不影响 |

## 七、收工自检清单

```
后端
□ 在 app/plugin/module_<域>/ 下，到 controller.py 的每级都有 __init__.py
□ routers.py 里没有我的痕迹（会自动重复注册，冲突即中止启动）
□ 每个业务单元五件套齐全：controller / crud / model / schema / service
□ 接口路径是 /<域>/<业务>/... 扁平形式，没有嵌容器名或目录名
□ 业务名能覆盖该目录下所有接口（不能只顾最主要的那个）
□ URL 用中划线，权限资源段用下划线 ← 最容易错，对照第三节表格
□ 分页参数是 Annotated[PaginationQueryParam, Depends()]，没有同级 Query 标量（见坑 6）
□ 列表接口实查过：换个筛选条件返回条数真的会变（别只构造对象调 service）
□ 权限串形如 module_<域>:<资源>:<动作>，动词在词表内
□ 表名前缀 = 域简名（或已确认的例外）
□ grep 全仓：<旧绝对路径> 与短名 module_<域>，零残留
□ 涉及的定时任务代码块已更新（如有）

前端
□ 页面是 index.vue + components/*Tab.vue，Tab 内容 v-if 惰性渲染
□ ElCard.fa-table-card 放在 Tab 子组件内，不是包在 ElTabs 外面
□ 一个页面一个 ts；多业务时 *_API_PATH 并列、常量名带业务前缀
□ 分页用 FaPagination，搜索用 FaSearchBar —— 没手写 .fa-pagination / .fa-search-form 样式
□ 表单 @submit.prevent 绑了 handler（回车要能查询）
□ defineOptions.name 是 PascalCase，带 inheritAttrs: false
□ v-hasPerm 用数组取值
□ Vite dev 能实际加载每个新组件

收尾
□ 菜单脚本跑过，幂等复跑零新建；旧节点软删除；原持有角色已改授（含按钮节点）
□ docs/adr/ 有决策记录；GLOSSARY.md 有新术语
□ 验证：新路由可达（401）、旧路由消失（404）、页面上真实查得到数据
```
