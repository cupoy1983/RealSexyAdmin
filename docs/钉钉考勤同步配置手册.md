## 一、它做了什么（原理）

```
钉钉云端 ──(1) 打卡结果──▶ 本系统后端 ──(2) 按手机号对号入座──▶ 考勤记录表
                                ▲
                                └──(3) 映射表：钉钉 userId ↔ OA 员工
```

- 拉的是钉钉的**打卡结果**（`attendance/list`），不是原始流水。钉钉按「上班卡 / 下班卡」各返回一条，本系统合并成一人一天一条。
- 迟到 / 早退分钟数用钉钉给的**基准时间**算，比本地班次规则更权威 —— 钉钉后台怎么设的考勤规则，同步过来就是什么结果。
- 状态映射：正常→正常，迟到 / 严重迟到→迟到，早退→早退，未打卡 / 旷工→缺卡。
- 同步时会顺带关联当天的排班班次（仅用于页面展示，不影响判定结果）。

**两个硬限制（钉钉侧定的）**：一次最多查 50 人，起止日期相隔最多 7 天，且不支持查半年前的数据。代码里已经自动分批分段，你不用管，但同步跨度很大时会慢一些。

## 二、前置条件（钉钉开放平台，必须你做）

用有管理员权限的账号登录 [钉钉开放平台](https://open.dingtalk.com/)，进入你的**企业内部应用**。

### 1. 开权限

在「权限管理」里申请以下权限点：

| 权限点 | 用途 | 不开会怎样 |
|---|---|---|
| 查询企业考勤数据权限 | 拉打卡结果 | 同步直接报「无权限」 |
| 通讯录部门成员读权限 | 拉通讯录名单 | 自动匹配拉不到人 |
| **企业员工手机号信息权限** | 拿到员工手机号 | **匹配全部失败**（返回的用户没有 mobile 字段） |

第三个最容易漏。手机号是钉钉 userId 与 OA 员工对上号的唯一桥梁，没有它整条链路就断了。

### 2. 拿凭据

在应用「基础信息 → 凭证与基础信息」里取：

- `AppKey`
- `AppSecret`
- `AgentId`（微应用 ID，可选，不填不影响考勤同步）

### 3. 确认部门 ID

「通讯录」里看你需要同步的部门 ID。**根部门是 `1`**。注意：钉钉的部门用户接口**不返回子部门成员**，如果员工分散在多个子部门，要么配根部门，要么分几次同步不同部门。

## 三、配置步骤（改 `.env`，你自己动手）

### 第 1 步：编辑 `D:\AI\Project\RealSexy-OA\docker\.env`

在文件末尾追加（把 `=` 右边换成你的真实值）：

```bash
# ── 钉钉考勤同步 ──
DINGTALK_APP_KEY=ding你的AppKey
DINGTALK_APP_SECRET=你的AppSecret
DINGTALK_AGENT_ID=你的AgentId

# 同步哪个部门（1 = 根部门/全公司）
DINGTALK_ATTENDANCE_DEPT_ID=1

# 每日自动同步：true 开启，false 关闭
DINGTALK_ATTENDANCE_AUTO_SYNC=true
# 每天几点同步（24 小时制）。建议设在打卡结算之后，例如 6:30
DINGTALK_ATTENDANCE_SYNC_HOUR=6
DINGTALK_ATTENDANCE_SYNC_MINUTE=30
# 每次回溯几天。1 = 只同步昨天（推荐，钉钉当天结果次日才稳定）
DINGTALK_ATTENDANCE_SYNC_DAYS=1
```

> **安全提醒**：`.env` 里的 `AppSecret` 是明文。别提交到 Git、别截图外发。后端接口对外只返回「是否已配置」，不会把 Secret 下发到浏览器，这点已经处理过了。

### 第 2 步：重启后端让配置生效

```bash
cd D:\AI\Project\RealSexy-OA\docker
docker compose up -d --no-deps backend
```

### 第 3 步：确认应用起来了

```bash
docker compose ps          # backend 应为 Up (healthy)
docker compose logs -f backend
```

启动日志里看到这一行就说明定时任务挂上了：

```
✅ 钉钉考勤每日同步 已注册：每天 06:30（回溯 1 天）
```

## 四、验证清单（按顺序做）

进入系统：**内务中心 → 考勤管理**

### 1. 先看配置有没有读到

打开「考勤记录」页，点右上角**同步钉钉考勤**。

- 如果弹出黄色提示「服务端尚未配置钉钉 AppKey / AppSecret」→ 环境变量没生效，回到第 2 步重启，并确认 `.env` 里没有多余空格或引号。
- 没有黄条 → 配置已读到，继续。

### 2. 建映射关系

进入「**钉钉账号映射**」页 → 点**按手机号匹配**。

系统会拉钉钉通讯录，用手机号和 OA 员工表比对：

- 匹配上的人直接建好映射；
- 对不上的会弹窗列出名单 —— 这些人**在 OA 里没有相同手机号**，去「系统管理 → 用户管理」把手机号补全，再点一次匹配。

> 你现在库里 3 个用户的手机号是 `13800138000` 这类占位数据，真实员工的手机号必须先录准，否则同步出来全是孤儿数据。

### 3. 试同步一次

回到「考勤记录」→ 同步钉钉考勤 → 选最近 7 天 → 开始同步。

弹窗会显示：`拉取 N 条，新建 X，更新 Y，跳过 Z`。

- `拉取 0 条`：日期区间内没人打卡，或映射没建对，或权限没开。
- `跳过` 数很大：说明这些日期已有**人工录入**的记录，被保护住了。想强制覆盖就打开「覆盖人工」开关。

### 4. 看数据

同步完列表自动刷新。检查「上班打卡 / 下班打卡 / 迟到分钟 / 考勤状态」是否符合钉钉后台的结果。

## 五、常见报错对照

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `钉钉未配置，请先在服务端环境变量中设置...` | `.env` 没填或没重启 | 填完重启 backend |
| `钉钉获取 access_token 失败: [40001] ...` | AppKey / AppSecret 不对 | 去开放平台核对，注意别复制进空格 |
| `钉钉拉取考勤打卡结果失败: [60011] 无权限` | 考勤权限没开 | 回第二节开权限 |
| `钉钉拉取通讯录部门用户失败: [50004] 部门不在权限范围内` | 部门 ID 填错，或应用没授权该部门 | 改成 `1` 试试 |
| 匹配上 0 人 | 手机号权限没开，或 OA 手机号是占位数据 | 开权限 + 补真实手机号 |
| 拉取条数一直是 0 | 查的区间超过半年，或那几天确实没人打卡 | 换成最近几天再试 |

## 六、回滚

### 只想关掉自动同步

把 `.env` 里改成 `DINGTALK_ATTENDANCE_AUTO_SYNC=false`，重启 backend。手动同步按钮仍然可用。

### 想完全停用钉钉功能

`.env` 里把 `DINGTALK_APP_KEY` 和 `DINGTALK_APP_SECRET` 都清空，重启 backend。所有同步接口会返回「钉钉未配置」，其余模块不受影响。

### 想清掉同步进来的考勤数据

同步写入的记录备注固定为 `[钉钉同步]`，可以直接按备注筛出来删除：

```sql
-- 先看一眼有多少条，确认无误再删
SELECT COUNT(*) FROM internal_attendance_record WHERE description = '[钉钉同步]';

-- 确认后再执行（软删除，与页面删除行为一致）
UPDATE internal_attendance_record
SET is_deleted = 1, deleted_time = NOW()
WHERE description = '[钉钉同步]' AND is_deleted = 0;
```

> 人工录入的记录备注不是这个值，不会被误删。这也是为什么默认不开「覆盖人工」——保护你的手工修正。

### 想撤掉映射表

```bash
cd D:\AI\Project\RealSexy-OA\docker
docker exec backend sh -c 'cd /home && python main.py downgrade --env=dev'
```

只会删 `internal_attendance_dingtalk_user` 这一张表，不动其他考勤数据。

## 七、几个你可能想知道的细节

**为什么默认只同步昨天，不含今天？**
钉钉当天的打卡结果要等次日结算才准确。定时任务默认同步「昨天往前 N 天」，避免拉到半成品数据。手动同步时日期随便选，不受此限制。

**为什么重复同步不会乱？**
同一个人同一天在库里只有一条记录。再次同步时是更新，不是插入。但如果那条记录是**人工录入**的，默认会跳过不动，除非你明确打开「覆盖人工」。

**同步会不会覆盖我的手工修正？**
默认不会。同步只更新备注为 `[钉钉同步]` 的记录。人工改过的记录会被跳过，并在结果里计入「跳过」数。

**考勤组和排班要不要先建？**
不建也能同步 —— 迟到早退由钉钉的基准时间算。建了班次和排班，页面上会多显示班次名，仅此而已。
