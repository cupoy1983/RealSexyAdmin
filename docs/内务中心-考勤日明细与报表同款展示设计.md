# 内务中心 · 考勤日明细与「钉钉同款报表」展示设计（待确认稿）

> 目标：网页上展示的考勤报表与钉钉后台导出的
> `2026-9月考勤报表.xlsx` **版式一致**（行=人，列=1..30，周六日显示「六/日」并置灰）。
> 设计照参考代码 `dingtalk-sync` 的 `db_schema.py` / `monthly_report.py` 来，
> 表名统一加 `IAC_` 前缀（Internal Affairs Center）。
>
> **本文是待确认稿，确认后才动手改代码。**

## 一、Excel 版式拆解（设计依据）

`2026-9月考勤报表.xlsx` 共 48 列、两行合并表头：

| 段 | 列 | 内容 |
| --- | --- | --- |
| 前缀列（竖合并 A1:A2…） | A 姓名 / B 考勤组 / C 部门 / D 工号 | 钉钉侧快照 |
| 10 个统计列 | E~N | 应出勤、出勤、休息、迟到、严重迟到、旷工迟到、早退、上班缺卡、下班缺卡、旷工 |
| 请假（横向合并） | O~Q | 事假(天) / 病假(天) / 年假(天) |
| 考勤结果（横向合并） | R~AV | 按天铺开 30 列，每格是**当天**的文本（正常 / 休息 / 下班缺卡 / 病假09-02 13:00到09-02 17:30 0.5天） |

关键点：**「考勤结果」是日明细，不是月度汇总值**。所以要做成同款，必须有日明细表。

## 二、数据表设计（表名前缀 `iac_`）

现有前缀情况：库内已有 `sys_` / `task_` / `ecommerce_` / `internal_` / `agno_`。
内务中心现有的 3 张表是 `internal_account_binding`、`internal_account_dept_mapping`、
`internal_attendance_monthly_report`。

### 1. `iac_attendance_daily_report`（新增 · 日明细）

一行 = Excel 里的**一个日期格**。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | bigint PK | |
| `oa_user_id` | int | OA 用户（未绑定不入库） |
| `work_date` | date | 日期 |
| `month` | varchar(7) | 冗余，按月查不用做范围运算 |
| `day_of_month` | int | 冗余，pivot 成列时直接按它排序 |
| `group_id` / `group_name` | varchar(64) | 考勤组快照 |
| `day_status` | varchar(16) | 结构化状态，**见待确认 A2** |
| `late_minutes` / `early_minutes` | int | 预留，参考代码有、实际未填 |
| `check_in_at` / `check_out_at` | datetime | 预留，参考代码有、实际未填 |
| `is_workday` | tinyint | 是否应出勤日 |
| `raw_text` | text | **考勤结果原文**，展示与对账以它为准 |
| `approve_text` | text | 关联的审批单原文 |
| `synced_at` | datetime | |
| `status` | int | 沿用项目约定 0 启用 / 1 停用 |

唯一键 `(oa_user_id, work_date)`；索引 `(month)`、`(oa_user_id, month)`。

> ⚠️ 注意命名冲突：本项目里 `status` 是**软删除标记**（0 启用 / 1 停用），
> 参考代码用 `status` 表示考勤状态。所以日表用 **`day_status`** 表示考勤状态，
> `status` 仍作软删除用。

### 2. `iac_attendance_monthly_report`（月报 · 现有表改名 + 补字段）

在现有 `internal_attendance_monthly_report` 基础上：

- 新增 `group_id`、`group_name`（考勤组快照）
- `job_number` 已有但一直为 `None` → 开始填值
- 其余不变：`name` / `dept_name` 快照、10 个统计列、`leave_personal/sick/annual`、`synced_at`
- 唯一键仍为 `(oa_user_id, month)`

参考代码的注释说明了为什么要冗余存快照：报表是历史凭证，员工后来调部门、改名、换考勤组，
历史报表都应保持**当月**的样子，所以刻意不建外键、不级联更新。

### 3. `iac_account_binding`（绑定表 · 现有表改名 + 补字段）

现有 `internal_account_binding` 基础上新增钉钉侧快照：
`job_number`（工号）、`group_id`、`group_name`（考勤组）。

取值接口（**均已实测 errcode=0，无需额外申请权限**）：

| 要什么 | 接口 | 返回 |
| --- | --- | --- |
| 工号 | `POST /topapi/v2/user/get` `{userid}` | `result.job_number` |
| 考勤组（按人） | `POST /topapi/attendance/getusergroup` `{userid}` | `result.name`、`result.group_id`、班次 |
| 考勤组（全量） | `POST /topapi/attendance/getsimplegroups` | 实测返回 `DY-OFFICE`、`DY-仓库` |

### 4. `iac_account_dept_mapping`（部门映射 · 现有表改名）

字段不变。

## 三、程序逻辑

### 同步入口

仍由系统定时任务节点 `dingtalk_monthly_report`（每月 7 号同步上月）触发
`MonthlyReportService.sync_previous_month()`，**不新增硬编码调度**。

### 单人同步流程

```
1. 取已绑定钉钉的 OA 用户（system_type = dingtalk）；未绑定不同步（沿用既有规则）
2. 绑定表缺 job_number / group_id / group_name 时，调 getusergroup + v2/user/get 补一次
3. getattcolumns 定位列 id：10 个统计列 + 考勤结果(8150430) + 关联的审批单(8150444)
4. getcolumnval 分批（一次最多 20 列）取整月「日粒度」值
5. 写月报行 iac_attendance_monthly_report
   - 10 个统计列：按天值累加
   - 请假：从「关联的审批单」文案正则 (事假|病假|年假).*?([\d.]+)\s*天，
     按「整条文案」去重（跨天假同一张假条会在每天重复，不去重会把 4 天算成 16 天）
   - 快照：姓名 / 部门 / 工号 / 考勤组
6. 写日明细行 iac_attendance_daily_report
   - 逐日写 raw_text（考勤结果原文）、approve_text（审批单原文）
   - raw_text 与 approve_text 拼接时按片段去重（审批单文案有时会并进考勤结果）
7. 单人失败只记录 message，保留旧数据；按 (oa_user_id, month) / (oa_user_id, work_date) 覆盖 → 幂等
```

### 与参考代码一致的取舍

- 报表主体**只用 `getcolumnval`**，不用打卡流水算考勤；
- 打卡流水（`/attendance/list`）参考代码只用来取 groupId，本方案改为直接用 `getusergroup`，不需要它；
- 实际打卡时间（`v1.0/attendance/checkin/records/query`）参考代码的表结构预留了但**没真的取**，本方案同样留字段不填；
- 请假算法与参考代码 `parse_leaves()` 完全一致（同一个正则 + 同一种去重）。

### 页面

- 「考勤统计」页（月报）维持现状；
- 新增日明细展示：选月份 → 行 = 人、列 = 1..30 的 pivot 表格，
  表头周六显示「六」、周日显示「日」并置灰，单元格显示 `raw_text`，与 Excel 逐格对得上。

## 四、决策结果（用户已确认 2026-10-28）

| 编号 | 决策 |
| --- | --- |
| **A1** | 内务中心 4 张表**全部**统一为 `iac_` 前缀（现在还没数据，一次改干净） |
| **A2** | **不做** `day_status` 结构化状态，日明细只存 `raw_text` 原文 |
| **A3** | 预留字段**留空列**：`late_minutes`、`early_minutes`、`check_in_at`、`check_out_at`、`is_workday`（照参考代码） |
| **A4** | 不新增菜单、不加 Tab：**月报表每行一个「查看明细」按钮，点击弹出该员工当月的日明细清单** |
| **A5** | 绑定表的 `job_number` / `group_id` / `group_name` **每次月报同步时顺带刷新** |
| **A6** | 钉钉部门名与 OA 部门名保持一致 → 月报 `dept_name` **取钉钉部门名**（与 Excel 一致）；两边名称不一致时属于「部门映射」没配对，应在账号管理里修映射，不在报表里做兼容 |
| **A7** | **不做**导出 Excel 按钮 |
