# 换云服务器（腾讯云 → 阿里云）

只换外网那台云机，域名仍是 `admin.realsxy.cn`。库、后端、上传文件都在家里 Armbian，不动。
IP／frp token／私钥不进仓库，一律现查。`<尖括号>` 是占位符。
标了「未实测」的命令，跑之前先在这台机器上用 `--help` 或 `ls` 核对一遍参数。

## 阶段一：新机准备（不停机）

**1 买实例**（阿里云控制台，无命令）
包年包月且剩余时长够备案接入（这次要求**未实测**，下单前在备案流程里核对）。系统选干净的 Linux。

**2 装 1Panel，在里面装 OpenResty 和 frps**（新云机，界面里点）
装完确认两件事都成立：

```
docker ps --format "{{.Names}}\t{{.Image}}\t{{.Status}}"
ss -lntp | grep 7000
```

`docker ps` 里 openresty 和 frps 都是 Up，`ss` 能看到 7000 在听。

**3 抄旧云机现值**（旧云机，输出存你本机运维记录，别贴进仓库）

```
docker ps --format "{{.Names}}\t{{.Image}}\t{{.Ports}}"
ls -1 /srv/RealSexyAdmin
ls -1 ~/.acme.sh
docker inspect --format "{{json .Mounts}}" openresty
docker inspect --format "{{json .Mounts}}" frps
docker exec frps cat /etc/frp/frps.toml
crontab -l
```

`.Mounts` 里的 `Source` 就是这台机器 1Panel 存配置的目录，记成 `<旧数据根>`；在新机上用同样两条 inspect 记出 `<新数据根>`。
**别照抄 `/opt/1panel`**，各机不同。**也别在这些命令后面加 `2>/dev/null`**，那会把"路径猜错"和"没权限"吞成空白。
拿到 `<旧数据根>` 之后补跑这一条，看清站点配置文件叫什么名字：

```
ls -1 <旧数据根>/apps/openresty/openresty/conf
```

`frps.toml` 里要认出的是：监听 `7000`、那条 token、`proxyBindAddr` 把 18001 收到只对本机开放。
`crontab -l` 里 acme.sh 那条续期任务原样留着，第 5 步照它抄。

**4 把四样东西搬到新机**

先在新机上建站点目录（新云机）：

```
mkdir -p /srv/RealSexyAdmin
```

再在新机上从旧机拉（也可以反过来从本机推，方向随你）：

```
scp -r root@<旧云机>:/srv/RealSexyAdmin/. /srv/RealSexyAdmin/
scp -r root@<旧云机>:~/.acme.sh/admin.realsxy.cn_ecc ~/.acme.sh/
scp -r root@<旧云机>:<旧数据根>/apps/openresty/openresty/conf <新数据根>/apps/openresty/openresty/
scp -r root@<旧云机>:<旧数据根>/apps/frps/frps/data <新数据根>/apps/frps/frps/
```

前端页面别用上面拷过来的旧 `dist/`，改成本机重新构建再推（本机，仓库根起）：

```
cd frontend/web
pnpm install
pnpm run build
scp -r dist/. root@<新云机>:/srv/RealSexyAdmin/
```

域名没变，所以 `.env.production` 不用改，`frontend/web/README.md` 那套构建参数一个字不动。

然后改新机那份站点配置：`root` 指向 `/srv/RealSexyAdmin`；`ssl_certificate`／`ssl_certificate_key` 两行指向第 5 步
`--install-cert` 落盘的位置；`proxy_pass` 保持 `http://127.0.0.1:18001`（这是 frps 的隧道口，别改成别的端口或写死 IP）。
改完验证再重载（容器名以 `docker ps` 为准）：

```
docker exec openresty nginx -t
docker exec openresty nginx -s reload
```

**5 证书与自动续期**（新云机）
证书不手写路径复制，用 acme.sh 安装到 OpenResty 读的位置，并让它续期后自动 reload（**未实测**，`--ecc`／文件名以当次 `acme.sh --list` 和 `--help` 为准）：

```
acme.sh --install-cert -d admin.realsxy.cn --ecc \
  --key-file      <新数据根>/apps/openresty/openresty/conf/admin.realsxy.cn.key \
  --fullchain-file <新数据根>/apps/openresty/openresty/conf/admin.realsxy.cn.cer \
  --reloadcmd     "docker exec openresty nginx -s reload"
```

续期 cron 用 `crontab -e` 照旧机第 3 步抄来的那条改，抄完确认：

```
crontab -l
```

只拷证书不装续期 = 90 天后全站突然打不开。

**6 新机开端口**（阿里云控制台安全组，无命令）
入方向放 80、443、7000 和你自己的 SSH（来源限到你能用的网段，别开 `0.0.0.0/0`）。`7500` 不放，旧机那个洞别复制过来。
机器自身确认在听（新云机）：

```
ss -lntp | grep -E ':80 |:443 |:7000 '
```

**7 在新机上自测**（新云机，此刻公网还指着旧机，不冲突）

```
curl -s -o /dev/null -w "首页=%{http_code}\n" --resolve admin.realsxy.cn:443:127.0.0.1 https://admin.realsxy.cn/
curl -s -o /dev/null -w "参数接口=%{http_code}\n" --resolve admin.realsxy.cn:443:127.0.0.1 https://admin.realsxy.cn/api/v1/system/param/info
```

首页 `200` = 页面 + 证书 + 反代在新机身上是通的。参数接口 `200` = 新机 frps 到家里这条隧道也通了；
不出 200 就先看 `docker logs --tail 20 frps` 里有没有客户端登录成功，再看家里 `docker logs --tail 20 frpc`。

**8 提交「新增接入」备案**（阿里云备案系统，无命令）
主体资料不变，只办接入。之后等审批，旧机照常跑。

家里 frpc 的 `serverAddr` 已经是域名（2026-11-19 改完并验过），所以这一趟家里零操作。

## 阶段二：切解析（备案通过之后）

1. 本机先看解析托管在哪家、现在指向哪：

   ```
   dig +short NS realsxy.cn
   dig +short admin.realsxy.cn
   ```

   在前一天把 `realsxy.cn` 的 A 记录 TTL 调到 600 秒或更低（在解析托管那家的控制台改，DNSPod 就改 DNSPod）。
2. A 记录改成新机 IP（控制台）。
3. 本机确认真的指过去了（可能等一个 TTL 周期）：

   ```
   dig @1.1.1.1 +short admin.realsxy.cn
   dig @8.8.8.8 +short admin.realsxy.cn
   ```

4. 家里确认隧道跟着走了（家里 Armbian）。正常情况下它自己会重连；要立刻过去就重启一次：

   ```
   docker restart frpc
   docker logs --tail 5 frpc
   ```

   最后几行有 `login to server success` 就算跟上。日志里若还有 `dial tcp <旧IP>:7000 connection refused`，
   先对时间戳，那些通常是历史行。
5. 旧机什么都别动：不停服务、不删文件、不退订。

## 验收（本机跑）

```
curl -s -o /dev/null -w "首页=%{http_code}\n" https://admin.realsxy.cn/
curl -s -o /dev/null -w "跳转=%{http_code} 目标=%{redirect_url}\n" http://admin.realsxy.cn/
curl -s -o /dev/null -w "参数接口=%{http_code}\n" https://admin.realsxy.cn/api/v1/system/param/info
curl --http1.1 -s -o /dev/null -w "WSS握手=%{http_code}\n" https://admin.realsxy.cn/api/v1/ai/chat/ws
echo | openssl s_client -connect admin.realsxy.cn:443 -servername admin.realsxy.cn | openssl x509 -noout -enddate
```

首页 200；跳转 301／302 到 https；参数接口 200，且 `favicon`／`logo_url`／备案号原样还在；
WSS **403**（必须带 `--http1.1`，不带必得假 404，那是 curl 走 h2 的行为，别去改配置）；证书剩 30 天以上。
再浏览器真登一次，看到点的定时任务有一格执行记录——同时只能跑一套后端，两套会静默不执行。

## 回滚

A 记录改回旧机 IP（控制台），恢复时间等于你设的 TTL。本机确认可用 `dig @1.1.1.1 +short admin.realsxy.cn`。
frpc 认的是域名，A 记录改回去它自己跟着回来，不用动配置文件；等不及就家里 `docker restart frpc`。
前提：旧机服务没停、`/srv/RealSexyAdmin/` 和证书还在、旧 frps 还在听 7000。

## 旧机退订

新机跑过一次凌晨定时任务 + 一次月初考勤／账单动作再退（`ADR-0012`、`ADR-0008` 那些时点动作都靠持锁进程在跑）；退订前留快照。

## 三条只能记在这里的事

- `backend/env/.env.prod` 不在 Git、也没有模板，重装 Armbian 才发现没了就只能逐键重建 → 现在就单独备份到仓库外。
- 旧机的 `dist/` 比 `frontend/web/public/` 落后，缺三份 logo 的 svg，线上 404（2026-11-18 实测）→ 所以重构建、别拷旧的。
- 不做一键脚本：买实例、1Panel 应用商店、安全组、备案、DNS 这五件只能控制台里人办。
