## 一、ADR：号由工具发，文档由 CI 验

### 1.1 谁是发号者

| 东西 | 谁维护 | 说明 |
|---|---|---|
| `docs/adr/domains.json` | **人**（唯一手维护文件） | 域清单、中文名（`label`）、代码目录、术语表位置。2026-11-12 起 **不含 `adr_dir` 与 `reserve_upto`**：号段与域无关 |
| ADR 的号与文件名 | `node scripts/adr.mjs new <标题>` | 取全仓下一个号，建 `docs/adr/<NNNN>-<slug>.md`，打印可粘贴的引用写法 |
| `docs/adr/README.md`、`CONTEXT-MAP.md` | `node scripts/adr.mjs index` | 生成物，**手改视为违规** |
| 号段 / 引用可解析 / 引用不带域名 / 测试目录已登记 / 相对链接 | `node scripts/adr.mjs check` | 有违规退码 1 |

**永远不要手敲 ADR 号。** 需要挪号只用 `renumber`，且只用于刚建、还没被任何地方引用过的条目。

### 1.2 编号模型（2026-11-12 已按 §六.3 落地）

- **号全仓唯一，一条连续序列**：当前 `0001–0039`。`0001–0018` 是内务（从 RealSexy-OA 合并进来，号未改），`0019–0039` 是电商（旧电商号 `0001–0021` 各加 18）。
- **ADR 一律平铺在 `docs/adr/`**，没有分域目录，也没有 `docs/adr/system/`。不属于任何业务域的决策照样占一个号。
- 缺口不复用：`new` 取 `max(已有号) + 1`，不是"填第一个洞"。已废止的号永远躺在那儿。
- 旧模型（号只在域内唯一）换来的是合并零改写；2026-11-09 业务方拍板反过来要全局连续，2026-11-12 执行完毕：**21 份文件改名 + 70 个文件 544 处改写**（其中电商号 529、区间并写的裸尾号 10、markdown 链接里的文件名 2、`电商ADR-` 这种旧写法去域名 3）。**旧号 → 新号 = 旧号 + 18**，读 2026-11-12 之前的老句子时用，`docs/adr/README.md` 末尾也写了这条。

### 1.3 引用写法（由 `check` 强制，不靠记忆）

只有一种形式：**`ADR-<NNNN>`**。代码注释、文档、issue、commit message、聊天，全部一样，号前不加域名。

- `电商ADR-<NNNN>` 是旧模型（号只在域内唯一）下为"没有域领土的位置"造的 workaround；`check` 现在把带域名的写法**当错误报**。
- 要说这条决策属于哪个域，用正文说（`ADR-0022`，商品成本的单一来源），不要把域名编进标识符。`domains.json` 的 `label` 因此只剩两个用处：CONTEXT-MAP 里「中文名」那一列的取值，以及让 `check` 认得出旧写法并拒绝它——这是相对 §六.5「`label` 也去掉」的一处**有意保留**，去掉就得把域名硬编码进工具。（那一列原本叫「中文限定词」，2026-11-12 一并改掉：留着这个词等于在推荐一种闸会拦下的写法。）
- 域归属现在只决定「用哪份术语表、算哪块代码领土」，与编号无关。判不出归属哪个域 → **停下来问**，不许猜号。
- `docs/adr/legacy-citations.json` 那条棘轮（曾豁免 60 处 alembic 迁移里的裸号）**随旧模型一起删除**：全局号之下裸号本来就合法，没有可豁免的东西了。

## 二、编码规则

以《新建模块规范》全文为准，此处只列两边都必须守的硬线。

### 2.1 框架 vs 自研

| | 框架自带（不学、不改） | 自研（规范） |
|---|---|---|
| 后端 | `app/modules/{system,monitor,task,ai,generator,common}` | `app/plugin/module_<域>/` |
| 前端 | `views/module_system\|monitor\|task\|ai\|generator\|example` | `views/module_<域>/` |
| 注册 | `app/api/v1/routers.py` 手写 | `discover.py` 自动发现 |

- 业务代码一律进 `app/plugin/module_<域>/`，新增不碰 `app/modules/`。
- **删除框架代码 / 大范围修改框架代码：先停止编码**，列出文件、行、动作、原因、影响，逐条等确认，不允许先删后报备。
- 已批准的框架改动逐条记进 ADR-0006 那份清单（内务那条序列里的 0006，平铺在 `docs/adr/`）。
- `app/plugin/infra/` 是基础设施，不是模块：**不放 controller**（路由发现不扫它，且启动无警告）。

### 2.2 命名（最容易写错的一组）

| 东西 | 分隔符 |
|---|---|
| URL / controller prefix | kebab `sku-cost` |
| 权限串资源段 | snake `module_ecommerce:sku_cost:query` |
| Python 目录/文件、ts 目录/文件 | snake |
| ts 里的 API 常量 | `STORE_API_PATH` |
| Vue `defineOptions.name` | PascalCase + `inheritAttrs: false` |
| 表名前缀 | 域简名（`ecommerce_*`；已确认例外：内务用 `iac_*`） |

**URL 和权限串是反的**，写之前回看一眼对照表。

### 2.3 结构性硬线

- 每个业务单元五件套：`controller / crud / model / schema / service`；到 `controller.py` 的**每一级都要有 `__init__.py`**（少一个会中止整个应用启动）。
- 接口路径扁平、只跟业务实体走：`/ecommerce/sku-cost`，不嵌容器名也不嵌目录名。
- 分页参数必须 `Annotated[PaginationQueryParam, Depends()]`，**不许与 `search` 同级写 `Query()` 标量**——那样 `search` 恒为 `None`，不报错、返回全表。
- 控制器不要手工挂到 `routers.py`，重复挂载会被 `check_route_conflicts` 中止启动。
- 前端：`index.vue` 壳 + `components/*Tab.vue`，Tab 用 `v-if` 惰性渲染；`ElCard.fa-table-card` 放在 Tab 内部；分页用 `<FaPagination>`、搜索用 `<FaSearchBar>`，不手写 `.fa-pagination` / `.fa-search-form`（这两个类全局根本没定义）；表单 `@submit.prevent` 必须绑 handler。
- 菜单/权限：统一用**幂等脚本**（`scripts/sync_<域>_menu.py`），按钮节点也要进授权清单；改 `sql/sys_menu.json` 对已初始化的库无效。
- 定时任务的代码块存在 `task_cornjob_node.func` 字符串里，搬模块后必须重跑注入脚本（失败是静默的）。

### 2.4 验证

测试分两类：**A 类**是干净环境（sqlite + 内存假 Redis）就能判定的 pytest，**CI 跑这些**，实测 `uv run pytest tests` 2 passed / 4s；**B 类**是连本机 dev MySQL、拿真实业务数据跑的轮次脚本，断言里有 MySQL 专有错误码，**CI 跑不了也不该跑**（`pyproject.toml` 的 `norecursedirs` 已把 `live` 挡在 pytest 之外，实测改名成 `test_*.py` 也收不到）。两类的目录规矩见 §2.5。

| 改动类型 | 最低验证 |
|---|---|
| 后端业务代码 | `uv run ruff check app/plugin/module_<域>` + A 类全套 + 该域的 B 类轮次脚本 |
| 前端 | `pnpm run type-check`、`pnpm run lint`（显式 `pnpm run`，不用简写） |
| 只改文档/脚本/ADR | 只跑受影响的部分 + `node scripts/adr.mjs check` |
| 列表接口 | 换筛选条件真实返回条数要变；**别用"直接构造 QueryParam 对象调 service"来验证**，那绕过参数解析 |
| 涉及库的验证脚本 | 必须靠 `close()` 回滚，不许 `db.begin()` 正常退出即提交 |

新增回归一律按这个界限放：能脱离本机库判定的写成 A 类 pytest，放 `backend/tests/module_<域>/`；离不开真实数据的放 `backend/tests/live/<域>/`，**不许平铺在 `tests/` 根上，也不许把非本域的塞进别的域目录**（两个业务域合仓就混了）。开新的 `live/<域>/` 之前先把这目录名登记进 `docs/adr/domains.json`——`check` 的第 4 条认的就是它（§1.3）。

改完声称成功之前必须跑对应命令；没跑就说不验证，或者明说没验。

### 2.5 测试目录布局（编码规范级硬线，两边同等生效）

两个业务域共用**同一个测试根** `backend/tests/`，域与域之间靠子目录隔开，不靠文件名：

```
backend/tests/                      ← 唯一共用的东西是这个根 + 一份 conftest.py
├── conftest.py  test_main.py  test_migrations.py    上游自带，不属于任何域，别改
├── system/                         A 类 · 框架 / 跨域回归
├── module_ecommerce/               A 类 · 电商（干净环境判定得出来的那些）
├── module_internal/                A 类 · 内务（OA 已建）
└── live/                           B 类 · 离不开本机 dev 库
    ├── README.md                   逐份脚本的索引（操作性文档，随脚本同步维护）
    ├── ecommerce/                  B 类 · 电商
    └── internal/                   B 类 · 内务（有脚本那天再建）
```

- **T1 按域分目录**：A 类进 `backend/tests/module_<域>/`，B 类进 `backend/tests/live/<域>/`，跨域的框架级回归进 `backend/tests/system/`。
- **T2 不许平铺**：`backend/tests/` 根上只允许上游那三个文件。一次性脚本（`_tmp_*.py`、临时探针）不进 `tests/`，用完即删——写它的那一轮收工时就删，别留给下一个人猜。
- **T3 不许跨域串门**：电商的口径不写进 `internal/`，反之亦然。判据是"这条断言属于哪个业务模块"，不是"它在哪个文件里好找"。
- **T4 `conftest.py` 全仓只有一份**：它强制 sqlite + 内存假 Redis，是 A 类能脱离本机环境跑起来的唯一原因。第二份会让两边 fixture 互相覆盖，`pytest` 收集顺序一变就莫名变红。
- **T5 目录名对齐代码目录**：A 类用 `module_<域>`，和 `backend/app/plugin/module_<域>` 一一对应，删模块时代码与测试同名好核对；B 类用 `<域>`，父目录 `live/` 已经说明了性质，不重复前缀。
- **T6 开新域目录先登记**：先把目录名登记进 `docs/adr/domains.json`，再往里放脚本。牙齿是 `check` 的第 4 条——`backend/tests/live/<名>/` 与 `backend/tests/module_<名>/` 的 `<名>` 不在登记表里就报错（§1.3）。旧规矩里这条的牙齿是「`code_dirs` 决定这里能不能写裸号」，2026-11-10 建 `live/ecommerce/` 当天实测过两次报错（先是裸号，后是跨域索引文件里写裸号）；全局号之下那两条报错都不会再出现，但登记本身继续要。**代价说清楚**：第 4 条只认"这个域名存不存在"，不认"这个文件算不算这个域的"，所以 T3（不许跨域串门）从 2026-11-12 起没有机器兜底，靠 agent 自己判——这是 §六.5 当初预告的那笔账。
- **T7 B 类必须回滚**：`session.begin()` 里以异常退出，或显式 `rollback()`；收尾另开一个 session 自证库里一条没留。正常退出即提交过一次事故（2026-10-20 污染 dev 库）。
- **T8 B 类不许写死存量快照**：要断言"本轮没污染存量"，就本轮开头自取基线、结尾对拍，不许写 `== 1744` 这类数字。锁死快照的脚本会随数据变化自己变红，作废的先例是 `order_update_v1v9.py`。

## 三、文档规则

### 3.1 目录布局

```
CONTEXT-MAP.md                  ← 生成物，域→术语表→代码目录
docs/<域>/CONTEXT.md            ← 该域术语表：两边同名、同位置（由 domains.json 的 context 指过来）
docs/adr/domains.json           ← 唯一手维护
docs/adr/NNNN-*.md              ← ADR，全仓一条序列、平铺、不分域目录
docs/adr/README.md              ← 生成索引
docs/<域>/                      ← 该域设计文档与审计
docs/agents/                    ← 给 agent 看的规则（本文件、issue-tracker、triage-labels、domain）
scripts/                        ← 根级开发工具，不属于任何业务模块
```

- 一个新业务域 = 一个 `docs/<域>/` + 一份术语表 + 一对 `module_<域>` 目录。三样同词。（ADR 不在这一串里了：2026-11-12 起它不分域，见上。）
- 设计文档/审计文档命名 `<域>-<主题>-<轮次或日期>.md`，日期一律绝对日期 `YYYY-MM-DD`。
- **不要为一次任务写计划/决策分析类临时文档**，除非业务方要；结论写进该域设计文档和 ADR。

**术语表的格式（D5，2026-11-13 起两边统一）**——两份词表过去一名一姓、一处一个（电商根 `CONTEXT.md`、内务根 `GLOSSARY.md`），现在统一成 `docs/<域>/CONTEXT.md`，书写格式也统一，规矩就五条：

1. **H1**：`# <域语境名> (<英文名>)`，例：`# 电商店铺利润 (E-commerce Store Profit)`、`# 内务中心 (Internal Affairs Center)`。紧接着那一行范围说明的收口句一律写「**本术语表只定义领域语言，不含实现细节。**」
2. **固定节名 `## 语言`**（中文，不写 `## Language`），下面按主题用 `### <分组>`，不许把词条平铺成一长串。
3. **词条**：`**术语 (English)**:` 结尾半角冒号，定义从下一行起，可以跨多行。英文别名**只在该术语本来就有英文名时写**，不给中文词造一个。
4. **反例行**：`_Avoid_: 词1、词2（为什么不行）`——半角冒号加一个空格。有反例才写，不是每条必填（电商 79 条里 38 条有，内务 37 条全有），别为凑格式编造同义词。
5. **引用它**：正文一律写全路径 `docs/<域>/CONTEXT.md`（两份现在同名，裸写 `CONTEXT.md` 判不出哪个域）；markdown 链接写成 `./CONTEXT.md` 这种带前缀的形式，`adr.mjs check` 那道相对链接校验才管得住它。

合并成一份共享大词典**明确不做**（业务方 2026-11-13 定为「改成一个名字一个位置」）：两个域的词汇本来互不指称（实测 0 处），合一本 67KB 的词典让 agent 进哪个域都得读全量，还会把「摘模块 = 删 `docs/<域>/` 整目录」这条拔插感破掉——术语表得跟着模块一起删。

### 3.2 术语

- 输出里凡是用到域概念（issue 标题、重构提案、假设、测试名），用该域术语表里的词，不漂到同义词。
- 需要的那个词术语表里没有 → 要么是你发明了项目不用的说法（收回），要么是真实缺口（交给 `/domain-modeling`）。
- 术语表缺文件时**不要专门提**，按 `/domain-modeling` 懒建。

### 3.3 上游基线文档不算我们的真相（实测）

`REQUIREMENTS.md`（150KB，标题是「SaaS 多租户平台需求文档」）、`CONTRIBUTING.md`、`SKILL.md`、`CHANGELOG.md` 四个文件在两个 clone 里 **sha256 完全一致**，都是 FastApiAdmin 上游基线。

- 它们**不是**我们的需求，别当真相来源；真实需求在 `docs/<域>/` 与 ADR 里。
- 要改这四个文件之一 = 改动上游基线，两边必须一起改，且先问业务方。

## 四、提问与确认规则

### 4.1 什么时候问

- 只在**真的没有答案**时问：列问题前先查该域 ADR 与术语表，**已定的方向不许重开**（重开会让业务方翻脸，有案可查）。
- 一次问**一个真问题**。同一个维度上的三个变体不要包装成三个"备选方案"让他选。
- 判不出归属/口径时问，不要靠外推：业务方给的裁定**不要外推成半句新口径**写进 ADR；留白就问，或标注未决。
- 需要他拍的：把会改库里数字或界面报错行为的每一条单独编号列出，等逐条回复。

### 4.2 编号规矩（两边统一沿用这套）

- 一轮一个**字母前缀**（AB / AF / AG / AI / AJ / AK / AL / AN / AR…）。新一轮 = 新前缀。
- `<前缀>缺N` = 缺陷；`<前缀>N` = 需要业务方拍板的问题。
- **已定决议一律不重编号**。旧断言被推翻时**就地改判据、编号不变**，并在文字里写明是哪一轮修订的。
- 答复就地结号，不新开号；审计发现本身可以不编号。
- 每一笔挂账都要带「不做」选项和实测代价；当场销账的，把决定写进该文档的「本期明确不做」小节。

### 4.3 动手前必须点头的动作

- 停止编码类：删框架代码、大范围改框架、新增依赖、改上游基线文档、建新文件。
- 不可逆/对外类：`DROP`、硬删数据、迁移回滚、强推、部署到生产、往公开仓库加 CI。
- 数据库执行默认交业务方；他明确说"跑完告诉我"才由 agent 代跑。

### 4.4 汇报

- 用户语言：中文。
- 分层说清楚：**数据层**与**界面层**、**待建**与**现有缺陷**不能混着说。
- 不把子 agent 的结论原样转述成事实——自己读过再说。
- 收口总结不许复述带"改 X…不，仍是 Y"这种自我纠正。
