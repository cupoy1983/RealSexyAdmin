# Domain Docs

How the engineering skills should consume this repo's domain documentation when exploring the codebase.

## Before exploring, read these

- **`CONTEXT-MAP.md`** at the repo root: it lists every business domain, where its glossary lives, and where its code lives. It is generated by `node scripts/adr.mjs index` — never hand-edit it.
- **`docs/adr/README.md`**: the ADR index, same generator. Use it to look up what a number means.
- **`docs/adr/`** itself holds every decision of every domain, flat, in one continuous sequence. There is no per-domain ADR folder.
- The glossary and the design docs **of the domain you are about to work in**: `docs/<domain>/CONTEXT.md`, the rest of `docs/<domain>/`, and `backend/app/plugin/module_<domain>/`.

If a domain's glossary doesn't exist yet, **proceed silently**. Don't flag its absence; don't suggest creating it upfront. The `/domain-modeling` skill (reached via `/grill-with-docs` and `/improve-codebase-architecture`) creates it lazily when terms actually get resolved. To add an ADR, use `node scripts/adr.mjs new <title>` — it takes the next repo-wide number and creates `docs/adr/<NNNN>-<slug>.md`.

## File structure

This repo is **multi-context**: several business domains share one FastApiAdmin skeleton. Domains split the *code and the vocabulary*; they do not split the *decision log*.

```
/
├── CONTEXT-MAP.md                     ← generated, points at each domain
├── docs/
│   ├── ecommerce/                     ← 电商: CONTEXT.md (glossary) + design docs and audits
│   ├── internal/                      ← 内务: CONTEXT.md (glossary) + design docs and audits
│   ├── system/                        ← 全局: CONTEXT.md (cross-domain vocabulary, no code territory)
│   ├── agents/                        ← agent 共用的干活规矩：shared-rules.md / issue-tracker.md / triage-labels.md / pii-inventory.md（本文件就住在这）
│   └── adr/
│       ├── domains.json               ← the only hand-maintained file here: domain list, labels, glossary + code paths
│       ├── README.md                  ← generated index
│       ├── 0001-…0018                 ← 内务 decisions, merged in from RealSexy-OA, numbers unchanged
│       └── 0019-…0039                 ← 电商 decisions, renumbered +18 on 2026-11-12
└── backend/app/plugin/
    ├── module_ecommerce/              ← 电商 territory
    ├── module_internal/               ← 内务 territory
    └── infra/                         ← shared third-party layer, belongs to no domain
```

**A new domain ships with its own glossary.** Adding a domain means `docs/<domain>/CONTEXT.md` alongside the `module_<domain>` code pair, registered in `domains.json`, and the hand-drawn tree above gains a line in the same commit. The rule itself — 一个新业务域 = 一个 `docs/<域>/` + 一份术语表 + 一对 `module_<域>` 目录，三样同词 — lives in `docs/agents/shared-rules.md` §3.1; this file only points at it so the two cannot drift.

Two invariants:

- **One number, repo-wide.** `ADR-0004` names exactly one decision no matter which folder you are standing in. Nothing is domain-qualified.
- **The tool issues numbers.** `node scripts/adr.mjs new <title>` takes the current maximum plus one, so nobody can hand-pick a colliding one. `check` fails on a gap, a duplicate, or a citation that points at a number no file carries.

Because the sequence is repo-wide, the sibling clone `../RealSexy-OA` (same remote, same `master`) cannot keep issuing numbers alongside us: whoever writes `0040` first owns it. Coordinate by git — merge their commits, then continue. `reserve_upto` is gone; it only existed to keep two per-domain sequences from stepping on each other.

**Territory is exactly what `domains.json` lists in `code_dirs` — nothing else.** Since 2026-11-10 that includes the test folders: `backend/tests/module_<domain>/` (A-class pytest) and `backend/tests/live/<domain>/` (B-class round scripts that need the local dev database). Territory now answers one question only — *whose glossary, whose design docs* — it has no bearing on how you cite an ADR. Layout rules: `docs/agents/shared-rules.md` §2.5 (T1–T8).

## Running the tool

- Any agent that touches `docs/`, `CONTEXT*.md` or an ADR citation runs `node scripts/adr.mjs check` before claiming success.
- `CONTEXT-MAP.md` and `docs/adr/README.md` are generated output: a hand edit there is a bug, not a formatting choice. Re-run `index`.
- Before a merge or a handoff to the sibling clone, compare their highest ADR number with ours — with one shared sequence an uncoordinated `new` on either side is a collision.
- CI **is live**: `docs-adr` runs the same four commands on every push to `master` (green on `b354d0e9`, `f0d1c38e` and `6f7ed8b4`, 2026-11-13). It does not replace the local run — CI only speaks after the push. The `pull_request` trigger is configured but has no sample yet. Full cross-project contract: `docs/agents/shared-rules.md` (§1).

## Use the glossary's vocabulary

When your output names a domain concept (in an issue title, a refactor proposal, a hypothesis, a test name), use the term as defined in **that domain's glossary** (see `CONTEXT-MAP.md`). Don't drift to synonyms the glossary explicitly avoids.

If the concept you need isn't in the glossary yet, that's a signal: either you're inventing language the project doesn't use (reconsider) or there's a real gap (note it for `/domain-modeling`).

## Writing an ADR reference

One form, everywhere: `ADR-<NNNN>` — in code comments, in docs, in issues, in commit messages and in chat. No domain label in front of the number. `node scripts/adr.mjs check` fails the build when it finds `电商ADR-<NNNN>`: the label was the workaround for domain-local numbering, and that numbering is gone.

Say which domain a decision belongs to in prose when it helps the reader (`ADR-0022`, 商品成本的单一来源), never as part of the identifier. The domain names are still useful language — `domains.json` keeps each `label` for exactly that — they just aren't part of a citation.

If you can't tell which domain a decision belongs to, the question is about code and glossary ownership, not about the citation: `node scripts/adr.mjs new <标题>` places it in the flat folder either way. Ask when the ownership matters.

## Flag ADR conflicts

If your output contradicts an existing ADR, surface it explicitly rather than silently overriding:

> _Contradicts ADR-0025 (运费按子订单发货月归属), but worth reopening because…_
