# RealSexyAdmin 内务中心：账号管理与钉钉考勤月报

本文是已确认的业务逻辑说明，用于开发、验收和后续合并到 RealSexyAdmin 主目录。代码目前在派生目录开发，文档统一按 RealSexyAdmin 描述。

## 一、范围

本期只做两条主线：

1. 钉钉用户与 RealSexyAdmin 系统用户关联；
2. 钉钉智能考勤月报同步与展示。

快麦、企业微信只预留扩展能力，不开发实际接入。

## 二、菜单与页面

```text
内务中心
├── 账号管理
│   ├── 钉钉账号 Tab
│   ├── 快麦账号 Tab（空内容，预留）
│   └── 部门映射 Tab
└── 考勤管理
    └── 考勤统计（展示钉钉月度汇总）
```

班次管理、排班管理、请假登记、原始考勤记录页面全部取消。

## 三、原始数据清理

以下四张表及表内数据删除：

- `internal_attendance_shift`
- `internal_attendance_schedule`
- `internal_attendance_leave`
- `internal_attendance_record`

对应后端模型、CRUD、Service、Controller、路由注册、菜单权限，以及前端页面与 API 一并删除。账号绑定能力及绑定数据保留。

## 四、账号绑定规则

- 一个 OA 用户在每个外部系统最多绑定一个外部账号。
- 一个外部账号也只能绑定一个 OA 用户。
- 手机号在 OA、钉钉、快麦、企业微信各自系统内部唯一；同一员工可跨系统使用同一手机号。
- 未绑定时允许手工匹配一次；手工匹配要求双方手机号一致且均未绑定。
- 绑定成功后不允许修改匹配或解除绑定，绑错也不提供页面纠正入口。
- 快麦、企业微信通过外部系统类型预留，本期不实现。

## 五、新建 OA 用户联动钉钉

- 新建用户手机号必填且在系统内唯一。
- 所属 OA 部门必须已配置钉钉部门映射，否则创建失败。
- 钉钉没有该手机号成员：创建钉钉通讯录成员，取得 `userId` 后自动绑定。
- 钉钉已有该手机号成员且未绑定其他 OA 用户：直接自动绑定，不重复创建。
- 钉钉成员已绑定其他 OA 用户、同手机号成员不唯一、部门未映射、钉钉接口失败：整个创建失败，OA 用户也不保留。
- 这里创建的是钉钉企业通讯录成员，不是替员工注册个人钉钉账号。

## 六、绑定后修改手机号

- 修改后的手机号仍必须在系统内唯一。
- 已绑定用户修改手机号时，同步修改当前钉钉成员资料，不重新匹配、不换绑。
- 钉钉更新失败或新手机号在钉钉冲突时，整个修改失败，OA 手机号保持原值。
- 未绑定用户修改手机号不触发钉钉更新。

## 七、钉钉考勤月报

- 新建月汇总表，不建日结果表。
- 一个 OA 用户的一个月份只保存一条月汇总记录。
- 月报数值来自钉钉智能考勤报表，本系统不自行计算。
- 同步时可以使用接口返回的每日数值形成月度结果，但每日数据不落库。
- 只同步已绑定钉钉的 OA 用户，未绑定不同步、不入库。
- 重复同步同一用户同一月份时覆盖旧结果。
- 单个用户同步失败时保留其旧月报，记录失败，不影响其他用户。
- 同步结果使用系统定时任务执行日志，不另建同步日志表。

## 八、同步时间

- 使用系统定时任务节点，**每月 7 号同步上个月**；具体时分在节点任务中配置。
- 手动执行同一节点时，也同步上个月，不自动同步本月。
- 节点代码块只调用预先写好的同步 Service。
- `SCHEDULER_ALLOW_CODE_EXEC=True`。
- 删除业务模块内硬编码的 APScheduler 注册，避免重复执行。
- 删除不再使用的 `DINGTALK_ATTENDANCE_*` 配置；钉钉 AppKey、AppSecret、AgentId 继续保留在环境变量中。
