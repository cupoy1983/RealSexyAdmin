## 规范与访问边界

### P1：人工入口授权没有绑定具体登录窗口

位置：`infra/crawler/login_access.py` 的 `exchange`、`authorized`，以及 `session_api.py` 的入口签发。

浏览器 Cookie 仅记录一小时截止时间，不包含平台、会话名或窗口代次；窗口结束后没有撤销对应授权。离线固定时钟探针证明，原窗口十五分钟期限后再兑换新票据，旧 Cookie 依然授权成功。因此不能依赖一次性入口票据阻止旧页面访问后续账号窗口。

修复验收：授权绑定独立窗口代次；窗口取消、结束、切换或过期时失效。既要拒绝旧 Cookie 和尚未兑换的旧票据，也要断开已经建立的旧 noVNC WebSocket。仅将 Cookie 改短，或者只在 HTTP 授权时检查，都不够。

中心内用户是否共享账号是既定业务口径：商品中心现行设计不做用户映射。因此“没有个人账号映射”不直接作为违约缺陷。若以后需要按人隔离，需另行确认；不能把 Collector 的服务 owner 误称为商品中心用户 owner。

## 业务一致性

### P2：切换会话时伪造结果来源或串用登录状态

位置：商品中心 `CaptureSessionDialog.vue` 的 `latestJobByUrl`、`applySessionName`、`handleSubmitJob`。

同一链接先用 A 会话采集，再切 B 会话，允许继续使用 A 的商品结果，但不能将其实际任务来源改成 B，也不能将 A 的登录检查或异常显示成 B 的状态。复用商品结果本身不是缺陷。

修复验收：商品缓存按平台和规范 URL 共享，不含会话名；在所属业务调用方权限内先读 current。切换时废弃旧会话操作及状态响应，商品结果和编辑内容可保留，不伪造采集来源。请求完成后只更新它所属的商品或会话。

### P2：覆盖后的旧任务未跳转最新结果

位置：商品中心 `capture/service.py` 的 HTTP 错误翻译，以及弹框的 `tryFetchJobResult`、`handleSubmitJob`。

Collector 返回 HTTP 410 和替代任务 ID，但商品中心转成普通错误；固定幂等键继续命中旧任务，页面要求再采。最新成功数据已经存在，不应要求重新访问平台。

修复验收：直接按商品读取 current，或从任务元数据读取 `superseded_by`，有界且防循环地跟随；检查调用方、平台、规范 URL 一致，不要求会话名一致，再读取当前成功结果、更新缓存。无效替代、404、网络错误应分别处理，不能全部解释成“已覆盖”。

### P2：幂等重放的登录异常未刷新会话

位置：弹框 `handleSubmitJob` 的 `replayed` 分支。

重放任务处于 `needs_login`／`needs_verification` 时，该分支提前返回，跳过新任务路径的 `loadStatus`。应统一在两类终态后读一次状态；不额外强制打开浏览器。

### P2：人工登录保存后原页面不自动刷新

位置：弹框 `handleLogin`。

当前在打开登录窗口后立即查询，保存发生后没有完成通知、窗口焦点刷新或有界状态轮询。原弹框可能一直显示未登录。应在返回页面或收到完成信号后只读状态，并防止旧请求覆盖新作用域。

## 部署条件

- 商品中心需合并 HTTP 修复并重启后台，不能只刷新网页。
- 当前回环 API 地址只适用于开发笔记本；服务器上不能继续指向笔记本的 localhost。后端 API 可达与用户浏览器可达入口必须分别验证。
- API 与浏览器共用正式 HTTPS origin 可沿用 SDK 默认入口；若分别使用内网 API 和外网入口，商品中心须新增可信 `browser_origin` 配置并传入 SDK，当前没有该配置入口。
- 登录与任务服务需共享可写会话健康卷，任务服务授权卷保持只读；正常授权 TTL 为十二小时。
- 仅部署商品中心不要求合入选品迁移。如果把当前选品迁移也一起合入，两个领域分叉将形成双头，须先完成专门的迁移合并及空库、已有库验收；不能直接执行 `upgrade head`。
- Collector 浏览器继续独立部署在已验证的执行环境；不能把其浏览器依赖装进 ARM 商品后台环境。

完成上述修复后，须验收：登录保存后自动更新；切换会话共享商品结果且不串登录状态、不伪造来源；异常的新任务与重放任务均更新实际会话状态；跨会话 A 成功后 B 覆盖，读取 A 展示 B 且不新建 C；更新失败保留 B；旧窗口票据、Cookie、已连接 WebSocket 均不能进入下一窗口。最后再做生产网关、持久化和恢复验证。
