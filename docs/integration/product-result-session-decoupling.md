# 商品结果与登录会话解耦

业务方确认（2026-11-27）：账号之间的数据差异不作为商品结果的区别。此前“按会话名分别缓存、分别覆盖商品”的要求撤销，以本文件为准。

## 规则

- 在同一业务调用方权限范围内，商品由平台和规范商品 URL 标识；结果复用、当前版本与覆盖均不含登录会话名。不同业务调用方的服务权限边界保留。
- 登录会话只负责实际访问平台的授权和人工窗口。任务保留实际执行的会话名与来源时间，切换会话不能把已有结果的来源改成新账号。
- 账号专属价格等差异按本次确认不另分版本。成功更新可跨会话覆盖，失败不清空已有成功结果。history 显式历史模式保留原行为。
- 读取已有商品结果不要求当前账号已登录；只有实际新采集或主动更新才检查所选会话。普通读取优先使用现有结果，不因切换账号而新建任务。
- 请求幂等与商品身份不同：同一请求重试沿用原幂等键；执行账号或请求参数确实变化时使用新请求键。保留已有幂等冲突检查，不能把改变执行账号伪装成完全相同的请求。

## 查看、开始采集与主动更新

| 操作 | 处理规则 |
| --- | --- |
| 打开商品、查看结果、普通「开始采集」 | 优先读已有成功结果；没有成功结果且已有执行中的任务时显示其进度；两者均无时才检查登录并提交采集。 |
| 点击「重新采集／更新数据」 | 明确要求实际访问平台。已有成功结果不能拦截本次主动更新；创建新一轮执行请求。 |
| 同一轮执行中重复点击或网络重试 | 继续显示原任务进度，复用该轮任务 ID 与幂等键，不创建重复任务。 |
| 主动更新成功 | 展示新的成功结果，替换当前商品版本。 |
| 主动更新失败、需要登录或验证码 | 保留原成功结果并显示更新失败原因；按实际执行会话提示处理，不把旧结果当成本次新采集。 |

“旧任务覆盖后读取最新结果，不重采”只约束普通读取旧记录：已有更新结果时直接展示它。它不禁止主动重采，也不能让「重新采集」按钮变成仅从缓存取数据。

每次明确开始新一轮更新时生成新的幂等键；该键属于这一轮，发送失败、响应不确定或重复点击时仍用同一个键。不能每次 HTTP 重试都换键，也不能所有主动更新永远沿用第一次的固定键。正在排队或运行时，页面按钮进入忙碌状态，后端继续依靠同轮幂等保证不重复执行。更新过程中可保留旧成功结果，同时显示“正在更新”。

处理完登录或验证后，由用户明确再试时开启新一轮请求，不永久重放之前已经终止的失败任务。没有服务能力、网络错误、鉴权失败不能冒充“没有商品结果”而自动新建采集。

## 接口

新增 `POST /collector/v1/products/current`，请求为 `platform`、`url`，不传会话名。成功返回 `job` 与 `result`，包含实际采集任务及其执行账号来源；没有成功结果返回 404 `product_not_found`。共享 SDK 提供 `current_product(platform=..., url=...)`。

主动更新走现有 `submit`／`POST /jobs`，使用新一轮幂等键；当前 Collector 不会因有 current 结果而阻止新的提交。商品中心须区分普通读取和主动更新分支；无需增加 Collector 的 `force` 参数，更不能用 `sessions/check(force=true)` 代替重新采商品。

现有旧任务结果仍按原合同返回 410 `result_superseded` 和替代任务 ID，不暗中把旧任务的结果冒充成新结果。商品中心可直接按商品读取 current，也可有界、防循环地跟随 `superseded_by`；只核对调用方、平台、规范 URL，不再要求会话名相同。

例：任务 A 已成功，后来任务 B 成功覆盖 A。再打开旧任务 A 时读取 B 即可，不需要再访问平台创建 C。A、B 可以使用不同登录会话。

“幂等重放异常会话刷新”是指：重复提交返回的可能是之前已经失败、需要登录或验证码的任务；和新任务一样，应刷新该任务实际执行会话的状态。若界面已经切到其他会话，不得把旧任务异常套用到当前会话。不使用强制打开浏览器的检查代替只读状态刷新。

## 已有数据升级

Collector 私有 SQLite 使用独立的结果索引版本，启动时在事务内重建旧会话索引，按原任务提交顺序合并各会话的成功结果。较晚提交的成功结果为当前版本，保留有效字段及其原采集时间；失败任务不能抢占当前版本。

只在事务提交后由原有清理队列回收已替代结果文件，不动登录授权、浏览器 profile、选品批次和备份。升级失败回滚；重复启动不重复迁移。

部署升级前备份私有执行队列 SQLite。若要回到不认识新结果索引的旧镜像，应同时恢复对应数据库备份，不能只换回旧镜像继续写新索引。

## 验收

跨两个会话采同一商品只保留一个 overwrite 当前结果；旧任务可找到跨会话的新结果；后来的失败或旧任务迟到不覆盖新成功结果；history 与其他调用方隔离；旧 SQLite 可原子升级、重复启动结果不变；未登录也能读取成功结果；读取 current 不创建任务，不访问平台。

主动重采另须验收：已有成功结果时点击更新，必须产生一轮新的实际采集；该轮执行中连点与请求重试只对应一个任务；成功后展示新结果，失败时原结果仍可查看；普通读取已覆盖任务不得额外采集。另查登录／验证终态的新任务和幂等重放任务是否都只读刷新实际账号状态。

本轮结果：包含窗口授权修复在内的相关回归共 99 项通过；ADR 引用、敏感信息与差异格式检查通过。本次发布包含代码和 SDK；线上生效状态以实际部署验收为准。商品中心代码由另一 agent 按更新后的交接清单接入，双方完成后联合验收。
