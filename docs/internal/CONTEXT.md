# 内务中心 (Internal Affairs Center)

内务中心的账号关联与考勤月报上下文。本术语表只定义领域语言，不含实现细节。

## 语言

### 账号与绑定

**OA 用户**:
RealSexyAdmin 系统内的登录用户，也就是员工在本系统里的身份。
_Avoid_: 系统账号、登录账号、员工（员工在钉钉/快麦里另有身份）

**外部系统账号**:
员工在钉钉、快麦、企业微信等外部系统里的身份。钉钉侧具体指企业通讯录成员。
_Avoid_: 钉钉账号（太窄）、第三方用户（太泛）

**账号绑定**:
一个 OA 用户与一个外部系统账号之间建立的一对一关系。绑定后锁定，不允许改绑或解绑。
_Avoid_: 账号映射（旧叫法）、账号关联、匹配关系

**手工匹配**:
绑定发生前，由管理员按手机号把未绑定 OA 用户与外部系统账号对上号的一次性操作。
_Avoid_: 自动匹配、重新匹配、改绑

**钉钉通讯录成员**:
被加入企业钉钉通讯录后形成的员工档案，有企业内 `userId`，用于考勤和接口调用。
_Avoid_: 钉钉账号、个人钉钉账号、企业账号

**部门映射**:
OA 部门与钉钉部门之间的对应关系，是新建 OA 用户时创建钉钉成员的依据。
_Avoid_: 部门同步、组织映射

### 考勤

**考勤组**:
钉钉侧把员工分组、按组排考勤规则（上下班时间、休息日）的单位，一个员工只属于一个考勤组。
来自钉钉 `getusergroup`，按 userId 反查。不属于任何考勤组的人，钉钉不会给他出考勤结果。
_Avoid_: 排班组、班组、考勤部门（与「部门」是两回事）

**考勤月报**:
钉钉按自身考勤规则计算好的某员工某月份考勤结果，包括应出勤、出勤、迟到、缺卡、请假等。
_Avoid_: 考勤统计、考勤流水、打卡记录

**钉钉智能考勤报表**:
钉钉返回月报结果的接口能力，月报数值由钉钉计算，本系统不重新判定。
_Avoid_: 打卡结果接口、考勤流水接口

**考勤日明细**:
某员工某一天那一格考勤结果（如「正常」「休息」「下班缺卡」「病假09-02 13:00到09-02 17:30 0.5天」），
对应钉钉导出报表里按天铺开的那一列。落库一行 = 一个日期格。
_Avoid_: 日报表、打卡明细、考勤流水

**考勤结果**:
钉钉对某一天出勤情况的判定文案，由钉钉计算，本系统原样保存、不重新判定。
_Avoid_: 考勤状态、出勤状态（本系统另有「状态」表示软删除，勿混用）

**关联的审批单**:
钉钉日明细里的另一列文案，记录当天关联的请假/补卡等审批信息，是推算请假天数的依据。
_Avoid_: 审批单、请假单

**公司休息日**:
公司在考勤组原有规则之外，按「日期 + 考勤组」临时安排的不必出勤的日子（不用打卡、不用上班），
组里全员一起休。钉钉不知道它的存在，由本系统记录并以钉钉月报为基准叠加它重新计算考勤。
_Avoid_: 额外休息、调休、福利假（都没点出"按考勤组整体安排"）

**考勤确认**:
管理员确认某月考勤数据与公司休息日安排已全部核对、登记完毕的动作，按月记录确认人与时间。
它是整月工资条生成的前置条件：未确认不生成；确认后要改休息日必须先撤销确认；
工资条一旦生成，考勤与休息日配置都不可再改（ADR-0018）。
它不是「绩效确认」（逐人确认绩效扣款），也不是超管对工资条的最终确认。
_Avoid_: 考勤审核、考勤审批、月度结账

### 页面与菜单

**内务中心**:
RealSexyAdmin 里承载内部行政事务的一级菜单，下有「账号管理」和「薪资考勤」两个页面。
代码位置固定在 `app/plugin/module_internal/`。
_Avoid_: 行政中心、后勤管理、internal 模块（说位置而不是名字）

**薪资考勤**:
内务中心下的页面，用页内 Tab 聚合两个业务：**考勤统计**与**薪资绩效**。
它本身没有数据表，两个 Tab 各自的业务才拥有独立接口路径。
_Avoid_: 考勤管理（旧菜单名）、考勤模块、工资考勤

**薪资绩效**:
薪资考勤页面的第二个 Tab，承载员工薪资档案、按月工资计算与工资条查询。
普通员工只能查看自己的工资条，管理员可管理月度绩效，超级管理员维护薪资档案并确认工资条。
_Avoid_: 绩效、工资、薪酬模块

### 绩效与扣款

**薪资档案**:
一个 OA 用户自己的月度薪酬基准，包括基础工资、全勤奖、固定补贴和绩效基准。
_Avoid_: 工资配置、薪资方案（容易被理解成全公司共用一套）

**绩效基准**:
某员工每月绩效的预设金额；当月实际绩效是绩效基准减去当月绩效扣款，最低为 0。
_Avoid_: 绩效工资（容易与最终实际绩效混为一谈）

**绩效扣款**:
因当月工作问题，从该员工绩效基准中扣减的金额，不是从基础工资中扣款。
_Avoid_: 绩效罚款、工资扣款

**绩效设置**:
管理员为有绩效奖金员工登记某月绩效扣款的动作；当月不扣款时也要设置 0。
绩效基准为 0 的员工不需要设置。设置完成后先供员工核对，不等于管理员已经确认。
_Avoid_: 绩效确认、绩效审批、工资确认

**绩效确认**:
管理员在员工核对后，对有绩效奖金员工当月绩效扣款（包括扣款为 0）的核对确认。
绩效基准为 0 的员工无需设置或确认。最后一名应确认员工确认后自动计算整月工资条；
工资条生成前可以撤销，生成后不能撤销。它与超级管理员对工资条的最终确认是两个不同动作。
_Avoid_: 工资确认、绩效审核通过

**无绩效奖金员工**:
薪资档案中的绩效基准为 0 的员工。无需管理员按月设置或确认绩效，实际绩效为 0，
但仍需核对考勤并参与工资条生成。
_Avoid_: 无绩效员工（省略后语义不清）、免考勤员工

**全勤**:
某员工当月实际出勤天数不少于应出勤天数。公司休息日仍上班会让实际出勤多于应出勤，这种情况照样算全勤。
除此之外不附加无迟到、无请假等条件。
_Avoid_: 满勤无异常、零请假

**缺卡扣款**:
按当月上班缺卡与下班缺卡的总次数计算的独立罚款，不并入基础工资的出勤折算。
_Avoid_: 考勤扣款（范围太宽，旷工和请假不在这里重复扣）

### 工资条与离职结算

**工资条**:
某员工一个自然月的薪酬计算结果及其计算依据。分「正式工资条」与「离职结算单」两种：
正式工资条由整月绩效确认后生成、超管确认后永久锁定；离职结算单在员工离职时按其考勤单独结算。
任何人不能撤销或修改。
_Avoid_: 薪资报表、实时工资单、工资表

**离职结算单**:
员工离职时按其考勤单独结算出的薪酬凭证，不需要超管确认，也不参与整月工资条生成。
_Avoid_: 离职工资条、结算工资表

**离职日**:
员工当月最后一个有考勤结果的工作日，用于离职结算单的展示与核对；不是管理员执行删除的日期。
_Avoid_: 删除日期、最后工作日、lastWorkDate（那是钉钉接口字段）

### 命名与表前缀

**IAC 前缀**:
内务中心（Internal Affairs Center）数据表的统一前缀，如 `iac_account_binding`、
`iac_attendance_monthly_report`、`iac_attendance_daily_report`。
_Avoid_: internal_ 前缀（旧）

### 离职与钉钉侧角色

**离职联动**:
删除 OA 用户时，同步把该员工在钉钉侧办理离职、并清掉账号绑定的那一整套动作。
OA 删除是主动作，钉钉是被带的一方；钉钉侧的离职不可撤销，所以整套动作先做全量预检、
全数通过才真正执行，任一人失败则整批不动。
_Avoid_: 删除同步、账号注销、离职同步（都没点出"谁带谁"）

**离职操作人**:
办钉钉离职时必须指名的另一名在职员工，按「本部门主管 → 上级部门主管 → 企业主管理员」
的顺序选取，不能是离职者本人。
_Avoid_: 经办人（太泛）、审批人（钉钉另有审批流的概念）、optUserId（那是接口字段名）

**部门主管**:
钉钉挂在**部门**上的负责人，一个部门可以有多个，与「管理员」不是同一套体系。
是离职操作人的首选来源。
_Avoid_: 部门管理员（钉钉没有这个角色）、部门负责人（钉钉只在管理后台这么叫）

**企业主管理员**:
钉钉企业的最高管理员，是离职操作人选取链的最后一档。
**本人不支持通过接口离职**，所以删除到他时会被引擎拦下，而不是办完再报错。
_Avoid_: 管理员（与子管理员混为一谈）、超级管理员（那是本系统 OA 侧的角色）

### 再入职与账号边界

**幽灵绑定**:
员工已离职、钉钉侧人已不在，本系统却仍留着的账号绑定记录。
它会挡住同一手机号再次入职，所以离职联动必须连带清掉它。
_Avoid_: 残留绑定、脏绑定、失效绑定

**重新入职**:
员工离职后再次以同一手机号加入。此时必须**复活**本系统那条已软删的 OA 用户记录并重新绑定钉钉，
而不是另建一条 —— 软删的记录仍然占着手机号的唯一约束。
_Avoid_: 重新建档（新建会撞唯一约束）、恢复用户（没说清还要重绑钉钉）

**普通用户**:
本系统 OA 侧的账号边界，指 `is_superuser = false` **且**角色仅为 `USER` 的账号。
两个条件缺一不可：`ADMIN` 角色即使不是超管也带管理权限。
管理员新增、编辑用户时只能落在这一档，超管不受此限。
_Avoid_: 普通账号（没界定角色）、员工账号（与是否参加考勤无关）、非超管（漏掉角色维度）

**账号 vs 姓名**:
本系统用户有两个易混字段：`username` 是**账号**，登录用；`name` 是**姓名**，真实姓名。
界面与接口描述统一用「账号」「姓名」，不再用「用户名」这个两可的叫法。
_Avoid_: 用户名（分不清指账号还是姓名）、名称（过于宽泛）
